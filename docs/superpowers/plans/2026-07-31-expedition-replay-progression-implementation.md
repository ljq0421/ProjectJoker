# 远征复玩、挑战与横向进度实施计划

> 对应设计：`2026-07-31-expedition-replay-progression-design.md`
> 实施方式：严格 TDD，每项由失败测试开始
> 文档边界：只暂存，不进入阶段代码提交

## Task 1：出发配置领域模型

1. 为三套固定起始牌组和六项挑战编写失败测试。
2. 验证十二张唯一牌、身份倾向、零至两项挑战约束。
3. 实现配置目录和公开说明。

## Task 2：远征会话与兼容存档

1. 为局次 ID、起始牌组、挑战快照和旧存档迁移编写失败测试。
2. 扩展远征会话、入口状态与存档格式。
3. 保证检查点恢复后配置不漂移。

## Task 3：六项挑战效果

1. 分别为目标、手牌、情报、价格、撤销和全台限制编写失败测试。
2. 在领域层接入挑战，不把规则只写在 UI。
3. 固定手牌谜题豁免精简手牌。
4. 验证所有单项与两两组合可以创建远征和首个区域。

## Task 4：横向进度与局史

1. 为首次通关解锁、幂等写入、三十条上限和损坏文件编写失败测试。
2. 实现独立元进度存储。
3. 在远征完成和失败终点各写入一次记录。

## Task 5：配置与历史界面

1. 新建独立配置场景，不修改主菜单现有布局结构。
2. 接入三套牌组、挑战锁定/组合、种子和历史列表。
3. 接入同配置重开。
4. 在区域和远征总结中持续展示当前配置。

## Task 6：验证与提交

1. 运行新增测试和全量测试。
2. 运行 22 种挑战配置的固定种子启动/可玩性检查。
3. 运行 1280×720、1920×1080 布局检查。
4. 真实鼠标完成配置、启动、历史重开和主菜单返回。
5. `git diff --check` 与差异边界审计。
6. 只提交 C 阶段代码/数据；A、B、C 文档保持已暂存未提交。
