# 《六面骗局》梦境电子玻璃音效设计规格

> 项目：Project Joker
>
> 日期：2026-07-26
>
> 引擎：Godot 4.6.1
>
> 目标分支：`master`
>
> 状态：已补充商用来源要求，等待书面规格复核

## 1. 背景

当前项目没有音频资产、音频总线布局或运行时播放服务。主遭遇、三轮流程、金线回廊、商店、刻印奖励和引导界面已经形成完整交互路径，但成功操作、错误反馈、弹窗变化和页面切换只能依靠视觉信息判断。

本次工作为这些既有交互增加一套“梦境电子玻璃”风格的一次性音效。声音必须帮助玩家分辨普通界面操作、骰子与卡牌动作、进程确认和结算结果，不改变任何玩法、布局或数据模型。

## 2. 已确认决策

- 在 `project-joker/master` 上工作。
- 覆盖核心玩法闭环和完整 UI。
- 声音气质采用梦境电子玻璃：清脆玻璃触点、柔和合成器脉冲和克制的低频落点。
- 本轮不包含背景音乐、持续环境氛围或语音。
- 建立可调音频总线，但不增加设置页面。
- 悬停和键盘焦点移动不发声。
- 只为已确认的点击、实际弹窗开合和实际页面切换发声。
- 成功动作播放成功语义音；被业务拒绝且界面显示错误时播放错误音；教程静默拦截不发声。
- 音频资产由项目内工具原创生成，不依赖外部素材或第三方许可证。

## 3. 目标

1. 让玩家无需持续阅读提示，也能区分选骰、放置、出牌、撤销、购买、安装和结算。
2. 为所有实际生效的普通按钮、弹窗和页面切换提供一致而克制的反馈。
3. 保证同一次操作只播放一个最具体的声音，不出现通用点击声与玩法声叠加。
4. 让页面切换音在旧场景销毁后仍可自然结束。
5. 让音效音量可通过 Godot 音频总线独立调整。
6. 保持音效系统与玩法 RNG、存档、领域模型和结算结果完全隔离。

## 4. 非目标

- 不制作或接入背景音乐、环境循环声、语音或角色台词。
- 不增加音量设置页、静音按钮或持久化音量配置。
- 不为鼠标悬停、键盘焦点移动、禁用按钮或教程静默拦截播放声音。
- 不改变现有 UI 布局、Theme、动画、文本、玩法数值或交互顺序。
- 不将音频调用放入 `RoundState`、`RoundResolver`、会话模型或其他领域层。
- 不为每个按钮制作独立文件；同一语义类别复用声音家族。

## 5. 方案选择

### 5.1 采用：中央语义音效服务

使用常驻 Autoload `SfxService` 管理事件映射、播放器池、音频总线、轻微音高变化和冷却。页面在业务操作确认后发送稳定语义事件，例如 `die_place` 或 `shop_purchase`。

该方案能够准确区分成功、错误和静默拦截，并允许转场声音跨场景继续播放。

### 5.2 不采用：全局按钮监听

全局监听无法知道按钮对应的业务操作是否真正成功，也难以避免通用点击声与专属玩法声同时播放。

### 5.3 不采用：每个场景自带播放器

场景内播放器会造成资源映射、音量和播放策略重复；页面切换时还会截断旧场景的尾音。

## 6. 架构

### 6.1 文件结构

```text
default_bus_layout.tres
resources/audio/sfx/
  *.wav
  manifest.json
  PROVENANCE.md
scripts/audio/sfx_service.gd
scripts/audio/sfx_access.gd
tools/generate_sfx.py
tools/verify_sfx_provenance.py
tests/sfx_service_test.gd
tests/sfx_ui_contract_test.gd
```

`tools/generate_sfx.py` 和 `tools/verify_sfx_provenance.py` 只使用 Python
标准库；游戏运行时不依赖 Python。

### 6.2 音频总线

音频总线链路为：

```text
UI ─────────┐
            ├─→ SFX ─→ Master
Gameplay ───┘
```

默认音量：

| 总线 | 默认音量 |
|---|---:|
| `Master` | `0 dB` |
| `SFX` | `-3 dB` |
| `UI` | `-6 dB` |
| `Gameplay` | `-2 dB` |

普通界面声使用 `UI`；玩法动作、错误、结算和里程碑使用 `Gameplay`。

### 6.3 `SfxService`

服务对调用方提供单一语义接口：

```gdscript
func play(cue_id: StringName) -> bool
```

UI 通过 `SfxAccess.play(self, cue_id)` 动态查找 Autoload。正常游戏会调用
常驻服务；Godot `-s` 独立主循环没有 Autoload 时安全静音，既有真实输入自检
仍可编译和运行。

返回值只表示播放请求是否成功进入播放器，不参与业务判断。服务额外发出只读测试信号：

```gdscript
signal cue_started(cue_id: StringName, bus_name: StringName)
```

每个事件映射包含：

- 音频流；
- 目标总线；
- 事件自身音量修正；
- 允许的轻微音高范围；
- 重复冷却；
- 播放优先级。

服务运行时创建 12 个 `AudioStreamPlayer`。优先使用空闲播放器；全部占用时，仅允许高优先级结算或错误音替换最早开始的低优先级 UI 声。未知事件、缺失资源或无可用播放器时返回 `false`，但不阻断游戏。

音高变化使用服务自己的独立随机源，不读取或改变任何玩法 RNG。

## 7. 声音语言

### 7.1 通用 UI

40–140ms 的轻薄玻璃触点或短促空气位移，音量最低，不使用明显低频。

### 7.2 骰子与卡牌

- 骰子：短促实体玻璃或晶体落点，具有可感知的重量。
- 卡牌：更轻的空气扫频和细碎高频，避免与骰子混淆。
- 校准：同一音色的上行与下行版本。
- 撤销：快速反向扫频，明确表达状态回退。

### 7.3 进程确认

路线、购买、安装和提交加入克制的低频落点或双音确认，比普通 UI 更有重量，但不达到结算强度。

### 7.4 结果反馈

使用 350–900ms 的短和弦：

- 成功为清晰上行和弦；
- 失败为收敛下行和弦；
- 区域完成在成功音基础上增加一层明亮尾音；
- 错误为短促低音告警，不使用刺耳蜂鸣。

## 8. 语义事件表

事件 ID 多于实际声音家族。相关事件通过音高方向、分层和轻微变体复用，预计形成约 16 个声音家族。

| 事件 ID | 触发条件 | 总线 | 声音家族 |
|---|---|---|---|
| `ui_confirm` | 普通按钮操作实际生效 | `UI` | 玻璃触点 |
| `ui_back` | 返回、取消或跳过实际生效 | `UI` | 回收触点 |
| `panel_open` | 弹窗从关闭变为打开 | `UI` | 轻柔展开 |
| `panel_close` | 弹窗从打开变为关闭 | `UI` | 轻柔收束 |
| `page_transition` | 已确认开始切换场景或页面 | `UI` | 空气位移 |
| `die_select` | 骰子选择状态实际改变 | `Gameplay` | 晶体拾取 |
| `die_place` | 骰子成功进入规则轨 | `Gameplay` | 晶体落点 |
| `die_return` | 骰子成功返回托盘 | `Gameplay` | 上行回收 |
| `card_select` | 卡牌选择状态实际改变 | `Gameplay` | 轻薄牌面触点 |
| `card_play` | 卡牌效果实际应用 | `Gameplay` | 空气扫频 |
| `calibrate_up` | 校准值成功增加 | `Gameplay` | 上行校准 |
| `calibrate_down` | 校准值成功减少 | `Gameplay` | 下行校准 |
| `undo` | 撤销实际改变状态 | `Gameplay` | 反向扫频 |
| `route_select` | 路线选择被领域会话接受 | `Gameplay` | 双音确认 |
| `shop_purchase` | 购买被商店会话接受 | `Gameplay` | 玻璃筹码确认 |
| `engraving_select` | 刻印、骰子或骰面选择实际改变 | `Gameplay` | 精密触点 |
| `engraving_install` | 刻印安装被领域会话接受 | `Gameplay` | 晶体锁定 |
| `round_commit` | 本轮首次成功提交 | `Gameplay` | 封印落点 |
| `round_success` | 回合或阶段结果为成功 | `Gameplay` | 上行短和弦 |
| `round_failure` | 回合、庄家或区域结果为失败 | `Gameplay` | 下行短和弦 |
| `area_complete` | 区域完成摘要首次打开 | `Gameplay` | 完成和弦 |
| `error` | 业务拒绝且界面显示具体错误 | `Gameplay` | 克制低音告警 |

## 9. 接入边界与数据流

统一数据流：

```text
玩家输入
→ 页面调用会话或领域操作
→ 检查 accepted 或比较实际状态变化
→ 刷新界面、改变可见性或开始页面切换
→ SfxService.play(语义事件)
```

### 9.1 主遭遇

`SingleEncounterScreen` 只在既有方法返回成功后播放：

- 骰子选择、放置和收回；
- 卡牌选择和实际出牌；
- 校准增加或减少；
- 撤销；
- 首次提交。

如果操作失败并更新 `ErrorLabel`，播放 `error`。如果教程在进入业务操作前拦截输入，则保持静音。

### 9.2 路线、商店和刻印

- 路线按钮只负责请求；`GoldCorridorRunScreen` 在 `select_route()` 返回 accepted 后播放 `route_select`。
- 商店选牌播放选择音；`purchase()` accepted 后播放 `shop_purchase`，失败并显示原因时播放 `error`。
- 刻印、骰子和骰面选择播放 `engraving_select`；宿主页在安装 accepted 后播放 `engraving_install`。

### 9.3 弹窗和结算

- 组件仅在 `visible` 真正发生 `false → true` 或 `true → false` 变化时播放开合声音。
- 结算面板根据实际状态选择 `round_success` 或 `round_failure`，不额外叠加 `panel_open`。
- 区域完成只播放 `area_complete`，不叠加普通成功音。

### 9.4 页面切换和普通 UI

- 页面切换在调用 `change_scene_to_file()` 前播放 `page_transition`；常驻服务保证尾音不被旧场景销毁。
- 引导继续、完成等纯 UI 操作播放 `ui_confirm`；返回、取消或跳过播放 `ui_back`。
- 具有专属玩法或转场语义的按钮不再播放通用 UI 声。
- 不使用全局按钮拦截器，不为悬停、焦点移动和禁用按钮发声。

## 10. 音频资产规格

- 采样率：48 kHz。
- 声道：单声道。
- 编码：16-bit PCM WAV。
- 时长：40–900ms。
- 峰值：至少保留 3dB 余量。
- 头尾：移除无意义静音，并使用极短淡入淡出避免波形点击。
- 生成：固定参数和固定种子，可重复生成相同输出。

生成器使用正弦波、不谐和泛音、短噪声包络、扫频和指数衰减组合出玻璃与合成器质感。所有声音均为原创合成，不采样外部作品。

## 11. 商用来源与追溯

### 11.1 已确认的权利边界

本项目不会下载、改编或混入任何第三方音效包、采样、循环、录音、旋律、游戏音频或预设演示素材。所有 WAV 都由仓库内可审计的数学合成代码直接生成，输入仅为数值参数、固定随机种子和基础波形。

OpenAI 当前适用条款说明：在用户与 OpenAI 之间、并在适用法律允许的范围内，用户拥有输出；条款同时明确输出可能不唯一，用户仍需自行判断输出是否适合具体用途。该条款不能被解释为不侵权保证或针对所有司法辖区的法律意见：

- [OpenAI Terms of Use，2026-01-01 生效](https://openai.com/policies/terms-of-use/)
- [OpenAI Services Agreement，2026-01-01 生效](https://openai.com/policies/services-agreement/)

因此，本项目采用“无第三方素材 + 可重复生成 + 全量来源记录 + 人工相似性检查”降低商用风险，但不声称风险绝对为零。如项目发行方需要正式的法律保证，应由其法律顾问完成最终审查。

### 11.2 禁用来源

生成与调音过程中禁止：

- 使用外部采样、音效包、循环或录音；
- 从其他游戏、影视、音乐或素材网站提取声音；
- 模仿指定作品的可识别旋律、标志性音型或商标性声音；
- 引入需要署名、限制商业使用、限制再分发或来源不明的资产；
- 使用生成器之外的二进制音频作为生成输入。

“梦境电子玻璃”只作为抽象材质与情绪描述，不以任何具体游戏、音乐人或商业音效库为模仿目标。

### 11.3 来源清单

`resources/audio/sfx/manifest.json` 为机器可读的资产清单。每个 WAV 记录：

- 文件路径和对应 cue ID；
- 生成器路径与生成器版本；
- 固定种子和参数摘要；
- 文件 SHA-256；
- 参数 SHA-256；
- 采样率、声道、位深和时长；
- `third_party_samples: false`；
- `generation_assistance: "OpenAI Codex"`；
- `commercial_review: "procedural_no_external_samples"`。

`resources/audio/sfx/PROVENANCE.md` 为人工可读说明，明确生成器代码由
OpenAI Codex 协助编写、资产由仓库内程序化合成、未使用第三方采样、不产生
外部素材库署名义务，并保留最终发行方自行法律审查的提示。

### 11.4 商用验收门

`tools/verify_sfx_provenance.py` 必须验证：

- 每个 WAV 都登记在 manifest 中，manifest 也不引用缺失文件；
- 当前文件哈希与 manifest 一致；
- 所有条目均声明未使用第三方采样；
- 生成器和参数摘要可追溯；
- 运行生成器后能得到相同文件哈希；
- 运行时引用的每个音频都在 manifest 中；
- 目录中不存在未登记的二进制音频。

最终人工试听还要确认没有可识别的第三方旋律、品牌提示音或对具体作品的明显模仿。未通过来源检查的音频不得接入运行时，也不得进入发行构建。

## 12. 冷却与重叠

- 普通 UI 同事件冷却为 35ms。
- 错误音冷却为 120ms。
- 结算与区域完成事件冷却为 300ms。
- 骰子、卡牌、校准和撤销允许快速连续播放，但通过轻微音高变化降低机械重复感。
- 一次输入只选择最具体的一个事件；例如成功购买只播放 `shop_purchase`，不播放 `ui_confirm`。

## 13. 容错

- 未知事件：输出开发警告并返回 `false`。
- 音频流缺失或无法加载：输出开发警告并保持静音。
- 目标总线缺失：回退到 `Master` 并输出开发警告。
- 播放器池耗尽：高优先级结果音可替换最早的低优先级 UI 声；否则跳过新请求。
- 音效失败不得改变界面状态、领域结果、存档或场景切换。

## 14. 自动验证

### 14.1 服务测试

`tests/sfx_service_test.gd` 验证：

- 所有事件 ID 均有可加载音频流；
- 音频格式、采样率、声道数、时长和峰值符合规格；
- 所有运行时音频均存在于来源清单且 SHA-256 一致；
- 事件被路由到正确总线；
- 播放器池支持重叠、冷却和优先级替换；
- 未知事件、缺失流和缺失总线安全失败；
- 音高变化不访问玩法 RNG。

### 14.2 UI 契约测试

`tests/sfx_ui_contract_test.gd` 验证：

- 成功操作只发出一次正确事件；
- 被业务拒绝并显示错误的操作只发出 `error`；
- 教程静默拦截不发声；
- 弹窗重复 show/close 不重复发声；
- 专属玩法事件不会叠加 `ui_confirm`；

## 15. 人工试听验收

沿真实输入路径检查：

1. 教学中的选骰、拖放、收回、校准、出牌、撤销和提交。
2. 三轮流程中的结算、继续、成功与失败。
3. 金线回廊的路线、商店、庄家、刻印和区域完成。
4. 所有引导按钮、弹窗开合、返回与页面切换。
5. 快速重复操作时没有爆音、双响、截断或明显音量跳变。
6. 只凭声音能够区分骰子、卡牌、普通 UI、错误和结算。
7. 没有可识别的第三方旋律、品牌提示音或对具体作品的明显模仿。

## 16. 完成条件

- 原创音效生成器和全部 WAV 资产存在并可重复生成。
- 来源清单、来源说明和验证脚本齐全，所有音频哈希一致且无未登记文件。
- 不包含第三方采样、外部音效包、受限许可素材或对具体作品的可识别模仿。
- `SFX`、`UI`、`Gameplay` 总线按规格加载。
- 核心玩法闭环和完整 UI 的确认事件均已覆盖。
- 没有悬停音、静默拦截音或通用声与专属声叠加。
