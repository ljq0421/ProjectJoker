# 《六面诡局》铁算盘进阶情境引导设计规格

- **日期：** 2026-07-26
- **状态：** 已确认，待实施计划
- **适用范围：** 普通三轮、替换商店、铁算盘、刻印安装与刻印验证组成的完整垂直切片

## 1. 背景

现有基础教程已经通过固定教学局教授三轨分配、校准、用牌、预览、撤销与确认结算，其固定路径为 `44→51→44→51`。

铁算盘垂直切片在此基础上新增了五类认知负担：

1. 三轮共享累计目标与跨轮继承。
2. 使用情报券替换牌，并将新牌组带入后续挑战。
3. 铁算盘庄家目标及随未分配骰子递减的固定奖励。
4. 从候选刻印、实际骰子、实际骰面组成一次安装决策。
5. 在验证局中观察刻印面被强制展示并确认效果触发。

当前界面已经提供规则文案和实时反馈，但 `iron_abacus_slice_screen.tscn` 明确关闭基础教程自动启动，也没有单独记录这些新增概念是否已经展示。因此玩家可能把刻印操作限制误认为界面失效，或在未理解跨阶段继承关系时作出不可逆选择。

## 2. 设计目标

- 首次进入完整垂直切片时，在五个阶段边界提供简短、可跳过的情境提示。
- 只解释新增规则和可观察结果，不指定最优策略，不要求玩家执行指定动作。
- 每个提示只自动出现一次；失败重试或返回同一阶段时不重复打扰。
- 允许永久关闭整套进阶引导，并提供主动重看入口。
- 引导显示、关闭、跳过和重看均不改变领域会话状态。
- 延续现有霓虹界面、键盘操作、安全区域和双分辨率适配规则。
- 保持低赌博表达，不新增下注、筹码、充值、借贷或概率触发设计。

## 3. 非目标

- 不重写或扩展现有基础三轨教程的固定教学动作。
- 不新增强制教学局、推荐流派、最优解提示或自动操作。
- 不将引导状态用作玩法解锁、奖励发放或阶段推进条件。
- 不修改铁算盘、刻印、牌组、情报券、RNG 或结算公式。
- 不为每种刻印分别制作一套长教程。

## 4. 已确认的体验原则

采用“聚焦提示卡”：

- 提示出现时以约 45% 遮罩压暗页面，并框出相关区域。
- 提示层暂时拦截背景输入，避免误触。
- 玩家点击“知道了”后立即恢复自由操作。
- 后续操作不受引导限制，也不校验玩家是否采用某种策略。
- 每张卡显示进度、标题、两至三句说明及“知道了 / 不再提示”。
- “不再提示”永久关闭整套进阶引导。
- 入口页保留“重看进阶引导”，用于重新体验完整提示流程。

这种短暂输入拦截只保证提示能够被看见，不构成动作门禁。

## 5. 五个情境提示点

### 5.1 普通三轮

- **触发时机：** 新垂直切片完成普通房界面绑定后。
- **聚焦区域：** 累计目标、当前轮次和情报券状态。
- **标题：** 三轮共同追逐累计目标

**核心说明：**

- 三轮共同追逐累计 `100` 分，而不是每轮单独达到 `100`。
- 本轮正式结算会进入下一轮。
- 成功后获得 `2` 张情报券。

本提示不重复骰子分配、校准、用牌、撤销或确认结算操作。

### 5.2 替换商店

- **触发时机：** 普通三轮成功后，替换商店首次完成会话绑定。
- **聚焦区域：** 情报券余额、当前牌组与替换操作区。
- **标题：** 替换会被后续挑战继承

**核心说明：**

- 每张情报券可替换一张牌。
- 每次替换同时移除一张旧牌并加入一张新牌，牌组保持 `12` 张。
- 离店后的牌组和剩余情报券会带入铁算盘。

引导不推荐购买目标，也不要求用完情报券。

### 5.3 铁算盘

- **触发时机：** 玩家从摘要进入铁算盘，庄家界面绑定完成后。
- **聚焦区域：** 庄家说明、实时固定奖励和结算轨迹。
- **标题：** 分配完整度影响固定奖励

**核心说明：**

- 铁算盘的三轮累计目标为 `150`。
- 固定奖励从 `12` 开始，每颗未分配骰子减少 `2`，最低为 `0`。
- 当前已分配数量和固定奖励会实时显示。

引导只说明取舍关系，不声称完整分配始终优于保留骰子。

### 5.4 刻印安装

- **触发时机：** 铁算盘成功后，刻印奖励面板完成绑定。
- **聚焦区域：** 候选刻印、骰子和骰面三个选择区。
- **标题：** 用三段选择确定一个刻印

**核心说明：**

- 先从三个确定候选中选择一种刻印。
- 再选择一颗实际骰子和它的 `1–6` 实际骰面。
- 安装前可以更改选择；只有三项齐全时才能确认安装。

引导展示每种刻印的已有说明，但不比较强弱或推荐组合。

### 5.5 刻印验证

- **触发时机：** 刻印安装完成，验证局界面绑定后。
- **聚焦区域：** 已刻印骰子、验证目标和结算轨迹。
- **标题：** 亲眼确认刻印触发

**核心说明：**

- 已选择的骰子会强制展示刻印面。
- 其余五颗骰子继续使用共享 RNG 得出结果。
- 刻印实际触发一次即可完成验证。
- 若刻印限制某项操作，界面会显示明确原因。

## 6. 交互合同

### 6.1 显示与关闭

- 每张提示卡标记为“进阶提示 `n/5`”。
- 默认键盘焦点落在“知道了”。
- `Enter` 等同点击“知道了”。
- `Esc` 关闭当前提示并记为已读。
- “知道了”和 `Esc` 都只关闭当前提示，不关闭后续提示。
- “不再提示”关闭当前提示，并永久跳过后续所有进阶提示。
- 提示关闭动画结束前保持输入拦截，结束后必须完全释放鼠标与键盘输入。

### 6.2 布局

- 卡片默认位于安全区域底部中央。
- 若卡片与聚焦目标相交，则选择顶部和底部中可用空间更大的一侧。
- 最终矩形始终限制在安全区域内，不依赖固定 `1280×720` 像素坐标。
- 聚焦框可以覆盖一个或多个目标，但不得改变目标控件的尺寸、布局或输入属性。
- 1280×720 和 1920×1080 下，卡片、聚焦框、按钮和文本均不得裁切。

### 6.3 重看入口

- 在现有“重看引导”和“进入六面诡局”所在入口区域增加“重看进阶引导”。
- 普通点击“进入六面诡局”不重置任何已读状态。
- 点击“重看进阶引导”只重置进阶引导状态，并从新的完整铁算盘切片开始。
- 重看不重置基础三轨教程完成状态。
- 重看使用正常的切片初始配置和种子，不直接跳转到中间阶段。

## 7. 状态与持久化

### 7.1 配置结构

继续使用 `user://onboarding.cfg`，新增独立区段：

```ini
[iron_abacus_guide_v1]
dismissed=false
seen_normal=false
seen_shop=false
seen_dealer=false
seen_reward=false
seen_verification=false
```

`dismissed=true` 时，不再自动显示任何进阶提示。五个 `seen_*` 状态保留各阶段是否已经确认。

### 7.2 写入兼容

现有 `TutorialProgressStore` 保存时会创建新的 `ConfigFile` 并直接写回。如果进阶引导与基础教程共享同一文件，两个存储器都必须先加载已有文件，再更新自己的区段；否则任一教程的保存可能覆盖另一教程的状态。

实施时必须：

- 修正 `TutorialProgressStore` 为“加载已有配置后更新自身键值”。
- 让新的进阶引导存储器采用相同的保留式写入。
- 将“文件不存在”视为正常初始状态。
- 将“文件存在但无法解析”视为持久化故障：使用全 false 的内存默认值、显示警告，并且本次运行不覆盖损坏文件。
- 保证基础教程的 `onboarding/done` 和进阶引导区段互不重置。

### 7.3 状态语义

- 提示只有在玩家点击“知道了”或按下 `Esc` 后才持久标记为已读。
- “不再提示”只写入 `dismissed=true`，不伪造五个 `seen_*` 状态。
- 主动重看将 `dismissed` 和五个 `seen_*` 全部重置为 `false`。
- 失败重试、庄家边界重试、验证边界重试和普通切片重开不自动重置进阶引导。
- 配置写入失败时，当前内存状态仍生效；界面显示非阻塞警告，下次启动可能再次显示对应提示。

## 8. 组件边界

### 8.1 `IronAbacusGuideProgressStore`

职责：

- 读取五个已读状态和整套跳过状态。
- 标记单个提示已读。
- 永久跳过。
- 仅重置进阶引导区段。
- 保留配置文件中的其他区段。

它不引用场景节点或领域会话。

### 8.2 `IronAbacusGuideFlow`

职责：

- 定义五个稳定的提示 ID。
- 根据提示 ID、持久化快照和内存会话状态判断是否应显示。
- 提供标题、说明和目标描述。
- 保证同一提示在当前运行中最多请求一次。

它是可同步测试的纯状态对象，不读写文件，也不修改游戏。

### 8.3 `IronAbacusGuideOverlay`

职责：

- 渲染遮罩、聚焦框、提示卡、进度和按钮。
- 选择不遮挡目标的卡片位置。
- 拦截提示显示期间的背景输入。
- 提供确认、永久跳过和持久化警告反馈。

它通过信号报告玩家选择，不直接写配置或访问 `IronAbacusSliceSession`。

### 8.4 `IronAbacusSliceScreen`

职责：

- 在五个界面绑定完成点请求相应提示。
- 将当前可见控件解析为聚焦目标。
- 接收提示层信号并调用存储器。
- 在任何阶段切换前关闭旧提示。
- 在保存失败时显示非阻塞警告。

它不得因为引导状态拒绝领域操作或更改领域数据。

## 9. 数据流

```text
阶段界面完成绑定
  → IronAbacusSliceScreen 请求提示 ID
  → IronAbacusGuideFlow 检查 dismissed / seen / 本轮已请求
  → 解析聚焦目标并打开 IronAbacusGuideOverlay
  → 玩家选择“知道了”或“不再提示”
  → Overlay 发出信号并关闭
  → Screen 调用 IronAbacusGuideProgressStore
  → 保存成功：更新持久化状态
  → 保存失败：保留内存状态并显示警告
  → 游戏继续，IronAbacusSliceSession 未被访问或修改
```

## 10. 失败处理

- 聚焦目标缺失时记录开发错误，关闭当前提示并放行游戏。
- 目标缺失不持久标记为已读，以便修复后重新显示；但当前运行内不重复请求该提示。
- 页面切换、场景退出、失败摘要、重试和完整重开前先关闭提示层。
- 提示层收到无效提示 ID 时拒绝显示并放行游戏。
- 持久化路径不可写时显示“无法保存进阶引导状态；下次启动可能再次显示”的警告。
- 配置文件损坏时不覆盖原文件；当前运行使用内存状态并显示同类警告。
- 任何引导错误都不得阻止进入商店、庄家、奖励或验证阶段。

## 12. 自动化与验收

### 12.1 纯逻辑与持久化

- 五个提示 ID、顺序和文案完整。
- 每个阶段首次请求显示一次。
- 同阶段重试不重复显示。
- 单个已读状态不会影响其他提示。
- 永久跳过后所有后续提示均不显示。
- 重看只重置进阶引导。
- 基础教程和进阶引导在同一配置文件中互不覆盖。
- 配置不存在、损坏或不可写时采用定义的失败行为。

### 12.2 UI 合同

- 遮罩、提示卡、进度、按钮、警告和聚焦框节点存在。
- 打开提示时背景输入被拦截。
- 点击“知道了”、`Enter` 或 `Esc` 后背景输入恢复。
- “不再提示”发出独立信号。
- 无效或缺失目标不留下遮罩。
- 卡片位置限制在安全区域内。

### 12.3 完整真实输入

使用真实鼠标按下、移动、释放和键盘事件覆盖：

1. 进入普通三轮并关闭提示。
2. 完成普通三轮，进入商店并关闭提示。
3. 离店，进入铁算盘并关闭提示。
4. 完成铁算盘，进入刻印奖励并关闭提示。
5. 选择刻印、骰子和骰面，进入验证并关闭提示。
6. 完成验证。
7. 证明每次提示显示和关闭前后的领域会话快照完全一致。
8. 证明重试不重复提示。
9. 证明永久跳过阻止后续提示。
10. 证明重看恢复五个提示，但不重置基础教程。

### 12.4 布局与视觉

- 五张提示卡分别在 1280×720 和 1920×1080 下通过布局检查，共十个视觉状态。
- 卡片不遮挡其聚焦目标，聚焦框不越过安全区域。
- 文案、进度和两个操作按钮无裁切。
- 现有基础单场、基础教程、三轮流程与铁算盘垂直切片布局检查继续通过。

### 12.5 回归

- 基础教程固定 `44→51→44→51` 路径不变。
- 现有全部同步测试套件继续通过。
- 现有基础教程、三轮流程和铁算盘真实输入检查继续通过。
- 所有 Godot 无界面命令显式传入 `$env:TEMP` 下的可写 `--log-file`。
- 退出码为零后仍扫描 `SCRIPT ERROR` 和 `Failed to load script`。
- 源码扫描不新增下注、筹码、赌注、贷款、借贷、充值、真钱或概率触发词。

## 13. 完成标准

- 五个提示在正确阶段首次出现，关闭后不限制策略操作。
- 已读、永久跳过和主动重看语义与本规格一致。
- 基础教程和进阶引导的持久化状态互不覆盖。
- 引导显示、关闭、跳过和重看不会改变任何领域状态。
- 所有失败路径均优先放行游戏并提供足够诊断。
- 双分辨率、真实输入、状态不变和全量回归验收全部通过。
- 设计与实施计划只暂存，不纳入代码提交。
- `project.godot` 的现有未暂存修改保持不变。
