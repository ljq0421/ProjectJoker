# 《六面诡局》三轮牌组与商店阶段设计规格

> 项目：Project Joker
> 日期：2026-07-26
> 上位规格：`2026-07-24-six-sided-rulebreakers-design.md`
> 阶段：实施顺序第 4 阶段
> 状态：对话设计已确认，待书面规格审阅

## 1. 目标

本阶段把现有的单轮教学遭遇扩展为一个可玩的三轮普通房切片：

1. 使用固定种子投掷骰子并洗入十二张起始牌。
2. 三轮各抽四张，第三轮结束时恰好看完十二张牌。
3. 三轮累计解析值达到公开目标后进入商店。
4. 玩家使用情报券从三张候选牌中购买一张，并原子替换牌组中的一张旧牌。
5. 保持牌组容量为十二张，不引入扩容、概率触发或隐藏结果。

本阶段必须继续满足：

- 预测与正式提交共用 `RoundResolver`。
- UI 不自行计算解析值、余额或购买结果。
- 相同种子与相同操作序列产生相同骰值、手牌顺序和商店候选顺序。
- 现有首次引导及其确定性 `44→51→44→51` 路径保持不变。

## 2. 阶段边界

### 2.1 包含

- 十二张起始牌和三张商店专属候选牌。
- 自定义 `Resource` 卡牌内容与集中式卡牌目录。
- 三轮牌组循环、骰子投掷、累计解析值和轮次切换。
- 成功、失败、同种子重试和进入商店。
- 两张情报券的公开房间奖励。
- 三选一候选展示、旧牌选择、购买与牌组替换。
- 从现有教学页面进入三轮试局的可玩入口。
- 领域、布局和真实输入自动验证。

### 2.2 不包含

- 付费刷新和路线情报服务；二者依赖下一阶段的区域与路线系统。
- 六个普通房、三个庄家房和完整九场流程。
- 精解条件及其额外情报券奖励。
- 四十张最终卡牌、最终花色比例和完整构筑平衡。
- 新效果原语、骰面刻印、存档、主菜单或永久成长。
- 修改当前主场景配置。

本阶段的十五张牌是牌组与商店流程的首批可玩内容，不作为最终四十张内容的花色分布验收。

## 3. 现有基线与兼容约束

现有工程已经具备：

- `RunRng`：注入种子的骰子与洗牌随机源。
- `CardDeck`：十二张牌、每轮抽四张的基础牌堆。
- `SingleEncounterSession`：单轮交互适配。
- `RoundController`：动作历史、预览、撤销和提交。
- `RoundResolver`：统一生成预测与正式结算事件。
- `SingleEncounterScreen`：三轨单轮 UI。
- `SingleEncounterTutorial`：首次引导与重看引导。

本阶段不得把随机牌组直接塞入教学会话。教学仍使用
`SingleEncounterFixture.make_hand()` 中固定的四张牌和固定骰值。
三轮试局的三轮均继续使用当前教学房的三张规则台定义；不同房间和规则组合属于下一阶段。

当前工作区中的 `project.godot` 修改属于阶段开始前已有改动。本阶段不编辑、不暂存、不提交该文件。

## 4. 架构

### 4.1 `CardCatalog`

新增集中式卡牌目录，负责加载十五个卡牌 `Resource`，并提供：

- `all_cards()`
- `starter_deck()`
- `shop_pool()`
- `find_card(card_id)`
- `validate()`

十二张起始牌与三张商店牌使用稳定且唯一的 `StringName` ID。卡牌资源声明：

- ID
- 中文名称
- 中文规则文本
- 目标类型
- 效果原语与参数
- 展示标签

目录显式列出资源路径，不依赖文件系统遍历顺序。

### 4.2 `ThreeRoundEncounterSession`

新增纯领域会话，拥有：

- 初始种子和一个持续使用的 `RunRng`
- 十二张牌的牌组 ID
- `CardDeck`
- 当前轮次，范围 `1..3`
- 当前 `SingleEncounterSession`
- 每轮正式结算报告
- 累计解析值
- 当前状态：进行中、成功、失败
- 成功奖励的情报券数量

职责：

1. 开始遭遇时洗牌。
2. 每轮用同一随机源投掷六颗骰子并抽取四张牌。
3. 用卡牌目录把手牌 ID 解析为 `CardDefinition`。
4. 接收当前单轮已经正式提交的 `ResolutionReport`。
5. 原样累计该报告总计，不重新计算得分。
6. 前两轮生成下一轮；第三轮判断累计目标。
7. 成功时使用同一个随机源打乱三张商店候选的展示顺序。

默认种子为 `20260726`，累计目标为 `100`，成功奖励为 `2` 张情报券。

### 4.3 `ShopSession`

新增纯领域商店会话，拥有：

- 当前十二张牌组 ID
- 三张候选牌 ID
- 当前情报券余额
- 已售出的候选
- 最后一次结构化错误

购买接口同时接收候选牌 ID 与被替换牌 ID。执行顺序为：

1. 校验候选仍可购买。
2. 校验旧牌确实存在于当前牌组。
3. 校验余额不少于 1。
4. 在副本中执行替换。
5. 验证结果仍为十二张且不包含未知 ID。
6. 原子提交副本并扣除 1 张情报券。

任何校验失败都不得扣券、售出候选或修改牌组。

### 4.4 UI 适配

新增：

- `scenes/run/three_round_run_screen.tscn`
- `scripts/ui/three_round_run_screen.gd`
- `scenes/components/round_summary_panel.tscn`
- `scripts/ui/round_summary_panel.gd`
- `scenes/shop/shop_screen.tscn`
- `scripts/ui/shop/shop_screen.gd`

`ThreeRoundRunScreen` 复用一个 `SingleEncounterScreen` 实例。为此，
`SingleEncounterScreen` 增加受控会话注入和提交成功信号，但继续保留原有默认教学会话。

试局模式下：

- 关闭自动引导。
- 隐藏“重看引导”和“三轮试局”入口。
- 顶栏显示当前累计值、目标、轮次、种子和情报券。
- 正式提交后显示轮次摘要，不自动切换。

现有教学页面增加“三轮试局”按钮，通过
`SceneTree.change_scene_to_file()` 进入新场景。新场景提供返回教学页面的操作。

## 5. 卡牌内容

本阶段不增加新的效果原语，只组合已验证的：

- `adjust_die`
- `modify_coefficient`
- `repeat_table`
- `reverse_resolution`
- `link_neighbors`

### 5.1 十二张起始牌

| ID | 名称 | 目标 | 效果 |
|---|---|---|---|
| `starter_nudge_down_1` | 拨码 | 骰子 | 点数 -1 |
| `starter_nudge_up_1` | 推码 | 骰子 | 点数 +1 |
| `starter_nudge_down_2` | 深降 | 骰子 | 点数 -2 |
| `starter_nudge_up_2` | 跃升 | 骰子 | 点数 +2 |
| `starter_map_1` | 映射 | 规则台 | 系数 +1 |
| `starter_map_2` | 增幅映射 | 规则台 | 系数 +2 |
| `starter_repeat_1` | 复写 | 规则台 | 额外结算 1 次 |
| `starter_repeat_2` | 双重复写 | 规则台 | 额外结算 2 次 |
| `starter_stable_repeat` | 稳态复写 | 规则台 | 系数 -1，额外结算 1 次 |
| `starter_amplified_repeat` | 增幅复写 | 规则台 | 系数 +1，额外结算 1 次 |
| `starter_reverse` | 倒序 | 全局 | 反转结算顺序 |
| `starter_link` | 桥接 | 桌间槽 | 将左侧已解析结果传递到右侧 |

`系数 -1` 只能把正系数降低到最低 `1`，不能产生零或负系数。
结算器应在计算有效系数时实施这一最低值，而不是让 UI 修正结果。

### 5.2 三张商店专属牌

| ID | 名称 | 目标 | 效果 |
|---|---|---|---|
| `shop_precision_map` | 精密映射 | 规则台 | 系数 +3 |
| `shop_triple_repeat` | 三重复写 | 规则台 | 额外结算 3 次 |
| `shop_long_push` | 长距推码 | 骰子 | 点数 +3，最终点数仍限制在 1..6 |

候选牌只在本阶段商店出现，不进入起始牌组。

## 6. 三轮流程

1. 玩家在教学页面点击“三轮试局”。
2. 使用默认种子创建 `ThreeRoundEncounterSession`。
3. 洗入十二张起始牌。
4. 为稳定 ID `d1..d6` 分别投掷点数，并抽取第一组四张手牌。
5. 玩家使用现有三轨操作完成本轮。
6. `SingleEncounterScreen` 正式提交并发出同一份结算报告。
7. 三轮会话累计报告总计，显示轮次摘要。
8. 玩家点击“下一轮”，生成新骰值与下一组四张手牌。
9. 第三轮后：
   - 累计值达到 100：获得 2 张情报券并进入商店。
   - 累计值不足 100：显示目标差值，可同种子重试或返回教学。
10. 商店显示当前牌组与三个候选。
11. 玩家选择候选和旧牌，确认替换。
12. 玩家可继续购买，直到余额不足、候选售罄或主动离开。
13. 离开商店后显示本阶段完成摘要，可同种子再试或返回教学。

未使用手牌和已使用手牌都在轮次结束后离开当前轮；第三轮结束时十二张牌必须全部出现且不重复。
同种子重试会重新创建起始牌组、清空情报券和购买结果，不继承刚才的商店替换。
本阶段离开商店后只展示替换后的最终牌组；该牌组将在下一阶段接入后续房间，不在本阶段写入存档。

## 7. 界面

### 7.1 顶栏

三轮试局顶栏固定展示：

- “三轮试局”
- 累计解析值与目标，例如 `34 / 100`
- 当前轮次，例如 `2 / 3`
- 当前种子
- 情报券余额

### 7.2 轮次摘要

摘要层展示：

- 本轮解析值
- 累计解析值
- 当前目标差值
- 下一轮编号或最终判定
- “下一轮”“同种子重试”“进入商店”“返回教学”中的适用操作

不允许在摘要层背后继续操作三轨页面。

### 7.3 商店

商店采用固定横屏布局：

- 左侧：当前十二张牌，使用三列或四列网格。
- 右侧：三张候选牌、名称、规则文本和售价。
- 底部：当前情报券、选中的新旧牌、确认替换和离开按钮。
- 错误区：显示余额不足、选择缺失、牌不存在或候选售罄等中文原因。

花色语义与最终牌面美术不在本阶段验收，但目标类型必须同时用文字与轮廓/图标表达，不只依靠颜色。

## 8. 数据流

```text
固定种子
  → RunRng
  → CardDeck 洗牌 / 六骰投掷
  → ThreeRoundEncounterSession 创建 SingleEncounterSession
  → SingleEncounterScreen 发送既有动作
  → RoundController / RoundResolver 生成预览
  → 正式提交同一 ResolutionReport
  → ThreeRoundEncounterSession 累计报告总计
  → 成功时创建 ShopSession
  → ShopScreen 发送候选 ID + 旧牌 ID
  → ShopSession 原子替换
  → UI 绑定新牌组、余额和错误
```

UI、摘要层和商店界面不得直接修改牌组数组、累计值或余额。

## 9. 错误处理

- 十二张起始牌不完整：阻止启动，并列出缺失或重复 ID。
- 卡牌资源缺失或字段非法：内容验证失败，开发构建阻止进入试局。
- 重复提交同一轮：拒绝，不重复累计。
- 未提交就进入下一轮：拒绝并显示原因。
- 第三轮后继续抽牌：拒绝并保持最终状态。
- 未选候选或旧牌：确认按钮禁用，同时保留具体说明。
- 余额不足：不扣券、不改牌组、不售出候选。
- 未知旧牌或候选：不修改任何状态。
- 替换后不是十二张：回滚整个购买。

## 10. 测试与验收

### 10.1 同步领域测试

- 十五张卡牌均可加载，ID 唯一、规则文本非空、目标与效果合法。
- 起始牌组恰好十二张，商店池恰好三张且两者 ID 不重叠。
- 三轮每轮抽四张，合计恰好十二张且不重复。
- 相同种子产生相同骰值、抽牌顺序和候选顺序。
- 不同种子至少在一项随机结果上不同。
- 三轮累计只使用正式提交报告中的总计。
- 同一轮不能累计两次。
- 第三轮正确进入成功或失败状态。
- 购买成功扣除 1 张情报券并保持十二张牌。
- 每种购买失败都保持余额、牌组和候选状态不变。

### 10.2 一致性测试

- 每轮的预测总计等于正式提交总计。
- 三轮累计值等于三份正式报告总计之和。
- 卡牌组合效果仍通过同一个 `RoundResolver` 生成事件。

### 10.3 场景与真实输入测试

- 教学页面的“三轮试局”按钮可通过真实点击进入新场景。
- 三轮试局关闭引导并隐藏教学专用按钮。
- 提交后摘要层阻止背后输入。
- “下一轮”真实点击只推进一次。
- 商店真实点击可选择候选、选择旧牌并完成替换。
- 无效购买显示中文原因。
- 1920×1080 下顶栏、三轨、摘要与商店均不裁切。

### 10.4 回归验证

- 现有同步测试全部通过。
- 现有基础布局、基础真实输入、引导布局和引导真实输入检查全部通过。
- 引导的 `44→51→44→51` 路径不变。

所有 Godot 无界面命令必须使用
`D:\Godot\Godot_v4.6.1-stable_win64_console.exe`，并显式传入
`--log-file` 到 `$env:TEMP` 下的可写路径。退出码为零后仍需扫描
`SCRIPT ERROR` 和 `Failed to load script`。

## 11. 完成标准

- 玩家可以从现有页面进入并完成一个三轮遭遇。
- 十二张牌在三轮内全部出现一次。
- 累计目标、轮次、种子和情报券始终可见。
- 成功进入商店，失败显示明确目标差值。
- 商店能完成最多两次原子替换。
- 牌组容量始终为十二张。
- 相同种子完整复现三轮骰值、手牌和商店候选。
- UI 不复制解析或购买规则。
- 所有自动化与可视验收通过。
- 阶段设计与实施计划文档保持暂存，不进入代码提交。
