# 《六面诡局》金线回廊情境引导设计规格

- **日期：** 2026-07-26
- **状态：** 已确认，待实施计划
- **适用范围：** 正式金线回廊的路线选择、第一次情报交换、铁算盘与区域刻印
- **上位规格：** `2026-07-26-gold-corridor-area-run-design.md`
- **兼容规格：** `2026-07-26-iron-abacus-contextual-onboarding-design.md`

## 1. 背景

现有基础教程已经教授三轨分配、校准、用牌、预览、撤销与确认结算。
正式金线回廊因此可以假定玩家已经完成或主动跳过基础教程，不需要再次
教授单轮操作。

现有五点铁算盘进阶引导只接入独立原型
`iron_abacus_slice_screen.tscn`，覆盖一个普通房、一个商店、铁算盘、
刻印安装和刻印验证。正式金线回廊由
`gold_corridor_run_screen.tscn` 承载，新增两次公开选路、两个普通房、
两次商店和区域完成账目，同时取消正式流程中的刻印验证局。

正式界面已经公开目标、奖励、规则与牌组呼应，但尚未提供区域级情境
提示。玩家可能具备完整操作能力，却不理解一次选路或换牌如何影响后续
整个区域。

## 2. 已确认前提

- 正式区域只需要补充区域级策略信息。
- 不重复基础三轨教程。
- 不替玩家推荐路线、牌、刻印、骰子或骰面。
- 提示必须简短、首次出现、可跳过、可永久关闭。
- 提示显示与关闭不得改变任何玩法状态。
- 旧铁算盘原型、旧五点进阶引导和刻印验证局继续保留。
- 设计与计划文档只暂存，不提交。

## 3. 设计目标

- 在四个高价值阶段边界提供一次性聚焦提示。
- 解释公开取舍与跨阶段继承，不给出最优解。
- 第二次选路和第二次商店不重复打扰。
- 允许玩家独立重看正式区域提示。
- 保持基础教程、旧原型引导和正式区域提示的持久化状态互不干扰。
- 延续现有聚焦遮罩、键盘操作、安全区域和双分辨率适配规则。
- 保持低赌博表达，不新增下注、筹码、充值、借贷或概率触发文案。

## 4. 非目标

- 不新增强制教学局、指定行动或动作门禁。
- 不修改房间目标、商店价格、铁算盘规则、刻印效果或结算公式。
- 不修改区域 RNG、牌组、情报券、骰子或失败重试语义。
- 不在第二次路线、第二次商店、失败页或完成账目上增加自动提示。
- 不把旧五点引导进度迁移为正式区域提示进度。
- 不删除旧进阶引导或将其重定向到正式区域。
- 不把现有提示遮罩重构为新的通用组件体系。
- 不修改 `project.godot`。

## 5. 体验原则

正式区域采用四张“聚焦提示卡”：

- 提示显示时以现有遮罩压暗背景并框出真实界面区域。
- 遮罩暂时拦截鼠标与键盘输入，避免误触。
- “知道了”、`Enter` 或 `Esc` 关闭当前提示并记为已读。
- “不再提示”永久关闭整套正式区域提示。
- 提示关闭后立即恢复自由操作，不校验玩家采取的策略。
- 每张卡显示“区域提示 `n/4`”、标题、两至三句说明以及两个操作按钮。
- 页面切换前主动关闭提示，不保留跨页面输入层。

短暂输入拦截只保证提示被看到，不构成玩法动作门禁。

## 6. 四个情境提示点

### 6.1 第一次路线选择

- **提示 ID：** `route`
- **进度：** `1/4`
- **触发时机：** 第一次路线面板成功绑定两个候选后。
- **聚焦区域：** 左右两张完整路线卡。
- **标题：** 先比较，再选择

**正式文案：**

> 每个房间用三轮共同完成累计目标。目标、情报券奖励、三条规则与当前
> 牌组呼应均已公开；选择更适合当前构筑的路线。

本提示同时承担“三轮共享累计目标”的区域说明，选择路线后不再立即弹出
普通房提示，避免连续两次遮罩。

### 6.2 第一次情报交换

- **提示 ID：** `shop`
- **进度：** `2/4`
- **触发时机：** 第一个普通房成功，第一次商店完成会话绑定后。
- **聚焦区域：** 情报券余额、十二张当前牌组与三个候选。
- **标题：** 替换会影响后续整个区域

**正式文案：**

> 每次花费 1 张情报券，用一张候选牌替换一张旧牌；牌组始终保持
> 十二张。离店后的牌组与余额会带入第二个房间和铁算盘，也可以不购买
> 直接离开。

第二次商店不重复提示。引导不推荐购买目标，也不要求花完情报券。

### 6.3 铁算盘

- **提示 ID：** `dealer`
- **进度：** `3/4`
- **触发时机：** 第二次商店结束，铁算盘遭遇界面完成绑定后。
- **聚焦区域：** 庄家规则面板与实时结算轨迹。
- **标题：** 完整分配会保住固定奖励

**正式文案：**

> 铁算盘的三轮累计目标为 150。每轮固定奖励从 12 开始，每颗未分配
> 骰子使奖励减少 2，最低为 0；当前结果会在结算轨迹中实时显示。

引导只公开取舍关系，不声称完整分配始终优于保留骰子。

### 6.4 区域刻印

- **提示 ID：** `engraving`
- **进度：** `4/4`
- **触发时机：** 铁算盘成功，刻印奖励面板完成绑定后。
- **聚焦区域：** 三个刻印候选、六颗骰子与六个骰面。
- **标题：** 这次安装将封存区域

**正式文案：**

> 依次选择一种刻印、一颗骰子和它的 1–6 面；安装前可以自由修改三项
> 选择。正式区域安装后直接进入完成账目，不再进入刻印验证局。

引导不比较刻印强弱，不推荐安装位置。

## 7. 不出现提示的阶段

以下阶段不得自动出现新的区域提示：

- 第二次路线选择。
- 第二个普通房。
- 第二次情报交换。
- 普通房或铁算盘失败页。
- 同种子重试与整个区域重开。
- 区域完成账目。
- 返回入口。

如果第一次提示因聚焦目标缺失而无法打开，本次页面仍正常可操作；同一
场景实例内也不在第二次同类阶段补弹。

## 8. 持久化设计

### 8.1 配置区段

继续使用 `user://onboarding.cfg`，新增独立区段：

```ini
[gold_corridor_guide_v1]
seen_route=false
seen_shop=false
seen_dealer=false
seen_engraving=false
dismissed=false
```

基础教程、旧原型进阶引导和正式区域提示分别使用：

```text
[onboarding]
[iron_abacus_guide_v1]
[gold_corridor_guide_v1]
```

三者不得互相重置或覆盖。

### 8.2 写入语义

- 加载时只读取 `gold_corridor_guide_v1`。
- 保存时先加载整个现有文件，再更新本区段。
- 损坏或无法解析的现有文件不得被覆盖。
- “知道了”、`Enter` 与 `Esc` 将当前提示的 `seen_*` 写为 `true`。
- “不再提示”只写入 `dismissed=true`，不伪造四个 `seen_*` 状态。
- 主动重看将本区段五个值全部恢复为 `false`。
- 写入失败时，本次运行的内存状态仍生效；下次启动可能再次显示提示。

### 8.3 旧进度兼容

旧 `[iron_abacus_guide_v1]` 的 `seen_shop`、`seen_dealer` 和
`seen_reward` 不自动映射到新区域区段。正式区域的继承范围与刻印终点
已经改变，旧原型已读不等同于理解正式区域语义。

代价是体验过旧原型的玩家可能看到三个相似提示。每个提示只出现一次，
且可以通过“不再提示”一次性关闭，因此接受该重复成本。

## 9. 组件与接口

### 9.1 `GoldCorridorGuideProgressStore`

职责：

- 读取四个已读状态与一项整套关闭状态。
- 返回不可变用途的快照副本。
- 标记单个提示已读。
- 永久关闭整套区域提示。
- 仅重置 `gold_corridor_guide_v1`。
- 对损坏配置采取禁止覆盖策略。

建议接口：

```gdscript
snapshot() -> Dictionary
initial_load_error() -> Error
is_dismissed() -> bool
is_seen(checkpoint_id: StringName) -> bool
mark_seen(checkpoint_id: StringName) -> Error
dismiss_all() -> Error
reset() -> Error
```

### 9.2 `GoldCorridorGuideFlow`

职责：

- 定义四个稳定提示 ID、顺序、进度、正式文案和聚焦目标 ID。
- 根据持久化快照决定是否显示。
- 保证同一场景实例内每个提示最多请求一次。
- 拒绝未知提示 ID。

建议接口：

```gdscript
checkpoint_ids() -> Array[StringName]
card_spec(checkpoint_id: StringName) -> Dictionary
should_present(checkpoint_id: StringName, snapshot: Dictionary) -> bool
mark_requested(checkpoint_id: StringName) -> bool
```

正式区域重开不得调用清空本次请求记录的方法。主动重看通过创建新的正式
区域场景实例开始，不依赖原实例重置请求记录。

### 9.3 聚焦遮罩

正式区域复用现有
`scenes/components/iron_abacus_guide_overlay.tscn` 作为纯渲染器，在
`gold_corridor_run_screen.tscn` 中实例化为唯一节点
`GoldCorridorGuideOverlay`。

复用理由：

- 现有遮罩已经支持多目标聚焦、上下避让、双分辨率、安全边距和键盘关闭。
- 卡片规格的 `progress_total` 已可传入 `4`。
- 新建视觉副本会造成两套遮罩行为漂移。

为准确显示“区域提示 `n/4`”，现有遮罩的 `open_card()` 增加可选
`progress_label` 卡片字段；缺省值保持“进阶提示”，旧五点原型的界面
与卡片数据无需修改。新区域四张卡统一传入 `区域提示`。

本阶段不重命名 `IronAbacusGuideOverlay` 类，也不重构旧场景；内部命名债
不影响玩家界面，且超出本功能范围。

### 9.4 `GoldCorridorRunScreen`

新增配置：

```gdscript
@export var guide_auto_start: bool = true
@export var guide_config_path: String = "user://onboarding.cfg"
```

新增职责：

- 创建区域提示存储器和流程对象。
- 连接遮罩确认与永久关闭信号。
- 在四个界面绑定完成点延迟请求提示。
- 从真实子场景实例解析聚焦目标。
- 页面切换、失败、重开和返回前关闭遮罩。
- 显示持久化失败的非阻塞警告。

提示请求不得进入 `AreaRunSession`，也不得改变任何领域对象。

## 11. 请求与关闭数据流

```text
阶段界面绑定成功
→ call_deferred 请求提示
→ Flow 检查 dismissed / seen / 本次请求记录
→ 标记本次已请求
→ Screen 解析全部真实聚焦控件
→ Overlay 打开、显示焦点框并拦截输入
→ 玩家确认或永久关闭
→ Store 保留式保存
→ Overlay 关闭并释放输入
```

请求必须发生在容器生成动态卡牌、骰子或候选节点之后。遮罩打开后继续
监听遭遇页面刷新，只更新焦点框，不重新请求提示。

## 12. 重看入口与入口兼容

入口页保留并明确区分三个按钮：

1. `ReplayTutorialButton`
   - 显示文字：`重看引导`
   - 只重置基础三轨教学局。
2. `ReplayAdvancedGuideButton`
   - 显示文字：`重看铁算盘原型引导`
   - 保持现有行为，重置旧五点引导并进入旧原型。
3. 新增 `ReplayGoldCorridorGuideButton`
   - 显示文字：`重看区域提示`
   - 只重置 `gold_corridor_guide_v1` 并进入正式金线回廊。

`RunTrialButton` 继续显示 `进入六面诡局`，正常进入正式区域，不重置任何
教程状态，只显示尚未读过的提示。

重看入口只有在对应存储器 `reset()` 返回 `OK` 后才切换场景。重置失败时
留在入口页并显示“无法重置区域提示；仍可正常进入六面诡局”，避免进入
新场景后看不到本次请求重看的内容。正常进入按钮始终可用。

如果使用自定义配置路径，重看入口通过根窗口一次性元数据把路径传给新
场景；场景读取后必须立即移除元数据，避免污染后续普通启动。

## 13. 故障处理

### 13.1 聚焦目标缺失

- 任一提示所需目标不存在、未入树或全部目标无有效矩形时，不打开遮罩。
- 记录包含提示 ID 和缺失目标 ID 的明确错误。
- 保持背景页面可操作，不修改持久化已读状态。
- 保留本次已请求记录，防止同一场景实例在后续同类阶段突然补弹。

### 13.2 配置加载或写入失败

- 配置损坏时不得覆盖原文件。
- 引导按内存默认状态运行，并显示一次非阻塞警告。
- 玩家确认后即使保存失败也关闭提示并继续游戏。
- 本次内存状态阻止同一提示再次弹出。

警告写入当前可见页面已有的错误区域：路线页使用
`RouteErrorLabel`，商店使用 `ShopErrorLabel`，遭遇页使用
`show_external_error()`，刻印页使用 `show_error()`。不得为了引导错误
新增阻塞弹窗。

### 13.3 页面切换

以下操作开始前必须关闭遮罩：

- 选择路线并进入房间。
- 打开或离开商店。
- 进入铁算盘。
- 安装刻印。
- 失败后重开区域。
- 返回入口。

关闭操作必须幂等；遮罩已经关闭时再次关闭不得产生错误。

## 14. 玩法状态不变性

以下动作只能修改引导存储或引导 UI：

- 打开提示。
- “知道了”、`Enter` 或 `Esc`。
- “不再提示”。
- 重看区域提示。

除重看入口按设计创建一个新的正式区域会话外，提示交互前后以下状态必须
保持一致：

- `AreaRunSession.phase`。
- 当前与已选择路线 ID。
- 当前房间序号和已完成房间记录。
- 十二张牌组及商店购买历史。
- 情报券余额。
- 六颗骰子配置与刻印状态。
- 当前遭遇、商店和刻印候选。
- `RunRng` 快照。
- 当前轮数、累计分和正式结算报告。

## 15. 测试与验收

### 15.1 同步测试

`GoldCorridorGuideProgressStore`：

- 默认状态。
- 四个提示分别标记已读。
- 永久关闭不伪造已读状态。
- 重置只清空正式区域区段。
- 保存保留基础教程和旧进阶引导区段。
- 损坏文件不覆盖。
- 不可写路径返回错误但保留内存状态。

`GoldCorridorGuideFlow`：

- 四个稳定 ID 和固定顺序。
- 每张卡的 `区域提示` 标签、标题、正式文案、进度和聚焦目标。
- 已读提示不显示。
- `dismissed=true` 时全部不显示。
- 同一场景实例每个提示最多请求一次。
- 未知 ID 被拒绝。

### 15.2 UI 契约

- 正式区域场景拥有唯一 `GoldCorridorGuideOverlay`。
- 遮罩层级高于路线、摘要、商店、刻印和完成面板。
- 四组聚焦目标都能从正确子场景实例解析。
- 遮罩打开时 `mouse_filter=STOP`，关闭时恢复 `IGNORE`。
- 提示关闭后背景控件可以正常接收输入。
- 入口页同时存在三个重看入口和正常进入按钮。

### 15.3 真实输入

用首次状态从正常“进入六面诡局”入口完成一整次区域：

1. 第一次路线提示出现并拦截背景路线按钮。
2. 确认后可以选择路线。
3. 第一次商店提示出现；确认后可以买牌或离开。
4. 第二次路线和第二次商店不重复提示。
5. 铁算盘提示出现并可关闭。
6. 刻印提示出现并可关闭。
7. 安装刻印后直接显示区域完成账目。

另行覆盖：

- 在第一张提示选择“不再提示”后，其余三张不出现。
- `Esc` 与“知道了”等价。
- 同种子重开和失败重试不重复提示。
- “重看区域提示”只重置正式区域区段。
- 基础教程和旧原型重看入口保持原行为。

### 15.4 状态不变性

在四个提示点分别记录玩法状态快照，依次执行打开、确认、永久关闭和
`Esc`，比较第 14 节列出的全部字段。除引导状态外必须完全一致。

### 15.5 布局与视觉

在 `1280×720` 和 `1920×1080` 下检查四个提示，共八张画面：

```text
1280x720-route-guide.png
1280x720-shop-guide.png
1280x720-dealer-guide.png
1280x720-engraving-guide.png
1920x1080-route-guide.png
1920x1080-shop-guide.png
1920x1080-dealer-guide.png
1920x1080-engraving-guide.png
```

每张画面必须确认：

- 提示卡未裁切。
