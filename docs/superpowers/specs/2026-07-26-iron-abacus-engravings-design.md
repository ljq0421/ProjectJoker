# 《六面诡局》铁算盘与基础刻印阶段设计规格

> 项目：Project Joker
> 日期：2026-07-26
> 上位规格：`2026-07-24-six-sided-rulebreakers-design.md`
> 前置阶段：`2026-07-26-three-round-deck-shop-design.md`
> 阶段：实施顺序第 5 阶段的第一个子项目
> 状态：书面规格已确认，待实施

## 1. 目标

本子项目在现有三轮普通房与替换商店之后，增加一个完整且可验证的
“铁算盘庄家 → 刻印奖励 → 刻印验证”闭环：

1. 玩家完成当前普通房与商店。
2. 替换后的十二张牌和剩余情报券被带入铁算盘挑战。
3. 铁算盘以公开的固定奖励规则检验六骰利用率。
4. 击败庄家后，玩家从四种基础刻印中的三个确定性候选里选择一个。
5. 玩家把刻印安装到实际骰子的实际骰面上。
6. 玩家通过一轮明确标注的验证局看到刻印真实触发。

本阶段继续遵守以下总原则：

- 所有效果公开且确定执行，不包含概率触发。
- 预测与正式提交使用同一个 `RoundResolver`。
- UI 不计算庄家奖励、刻印触发、阶段状态或随机结果。
- 跨遭遇状态使用稳定 ID，不使用场景节点路径。
- 不修改 `project.godot`，不增加 Autoload。
- 设计规格和实施计划只暂存，不进入代码提交。

## 2. 阶段边界

### 2.1 包含

- 一个完整的铁算盘三轮庄家挑战。
- 庄家固定奖励与未分配骰扣减事件。
- 四种基础刻印：回声、锚定、桥接、棱镜。
- 四选三刻印候选、刻印选择、骰子选择和骰面选择。
- 一颗实际骰子的一个实际骰面安装一个刻印。
- 一轮公开强制所选刻印面朝上的刻印验证局。
- 普通房商店到庄家挑战的牌组和情报券继承。
- 同一随机流及庄家边界的确定性重试。
- 领域、内容、布局、真实输入和双分辨率可视验证。

### 2.2 不包含

- 完整金线回廊路线、公开房间二选一或两个普通房流程。
- 镜面夫人、无面主人及其庄家机制。
- 其余八种刻印或每局两个刻印的完整上限流程。
- 十八张规则台、四十张最终手法牌或完整花色分布。
- 付费刷新、路线情报服务或精解条件。
- 跨启动存档、主菜单、设置、无障碍选项或完整叙事。
- 下一地区的正式遭遇；刻印验证局明确属于阶段验证，不属于区域房间。

本子项目只安装一个刻印。上位规格中的“每局最多两个刻印”将在完整区域流程中接入，
不在本阶段用第二次奖励模拟。

## 4. 总体架构

### 4.1 `IronAbacusSliceSession`

新增纯领域会话 `IronAbacusSliceSession`，负责阶段状态和跨遭遇数据，不持有 UI 节点。

状态枚举为：

```text
NOT_STARTED
NORMAL_ROOM
SHOP
DEALER
ENGRAVING_REWARD
ENGRAVING_INSTALL
VERIFICATION
COMPLETE
FAILED
```

会话持有：

- 初始种子和唯一的 `RunRng`。
- 当前十二张牌组 ID。
- 当前情报券余额。
- 六颗骰子的持久配置。
- 当前阶段和当前子会话。
- 普通房边界与庄家边界的 RNG 状态快照。
- 本次展示的三个刻印候选。
- 已安装的刻印 ID、骰子 ID 和骰面。
- 最近一次结构化错误。

会话组合而不是复制以下已有职责：

- 普通房使用 `ThreeRoundEncounterSession`。
- 商店使用 `ShopSession`。
- 庄家仍使用参数化后的 `ThreeRoundEncounterSession`。
- 单轮操作仍使用 `SingleEncounterSession`。

每个阶段转换都返回 `OperationResult`。UI 只能请求阶段操作并绑定结果，
不能直接修改牌组、情报券、骰子配置或阶段枚举。

### 4.2 参数化三轮遭遇

`ThreeRoundEncounterSession` 增加可选构造参数：

- 注入的 `RunRng`。
- 初始牌组 ID。
- `EncounterDefinition`。
- `ResolutionContext`。
- 三轮累计目标。
- 成功情报券奖励。

旧调用不提供这些参数时，继续使用：

- 当前 `CardCatalog.starter_ids()`。
- `SingleEncounterFixture.make_encounter()`。
- 无庄家、无刻印的空解析上下文。
- 默认目标 `100`。
- 成功奖励 `2` 张情报券。

普通房仍沿用阶段四的随机顺序。父级会话在创建普通房前不额外消耗随机数。

### 4.3 RNG 状态和边界重试

`RunRng` 增加显式的状态快照与恢复接口，封装底层
`RandomNumberGenerator.state`：

- `snapshot_state()`
- `restore_state(saved_state)`

进入铁算盘前保存：

- 牌组 ID。
- 情报券余额。
- RNG 状态。
- 尚未安装刻印的六骰配置。

庄家同种子重试恢复这一边界，不重放普通房与商店，也不保留失败挑战期间消耗的随机数。
完整切片重试才恢复初始种子、起始牌组和零购买状态。

## 5. 内容资源

### 5.1 `DealerDefinition`

新增自定义 `Resource`：

- `id: StringName`
- `display_name: String`
- `rule_text: String`
- `fixed_reward: int`
- `penalty_per_unassigned_die: int`
- `tags: PackedStringArray`

本阶段只有：

| ID | 名称 | 固定奖励 | 每颗未分配骰扣减 |
|---|---|---:|---:|
| `dealer_iron_abacus` | 铁算盘 | 12 | 2 |

内容校验要求：

- ID 和中文名称非空。
- 规则文本非空。
- 固定奖励为正数。
- 扣减值为正数且不会让六颗未分配时产生负奖励。
- 至少有一个展示标签。

### 5.2 `EngravingDefinition`

新增自定义 `Resource`：

- `id: StringName`
- `display_name: String`
- `rule_text: String`
- `operation: EngravingOperation`
- `amount: int`
- `tags: PackedStringArray`

有限原语为：

```text
ECHO_ADJACENT
ANCHOR_DIE
BRIDGE_FORWARD
PRISM_PARITY
```

每种原语拥有固定目标和参数规则，内容资源不能执行独立脚本。

### 5.3 `EngravingCatalog`

目录显式加载四个资源路径，不依赖目录遍历顺序，提供：

- `all_engravings()`
- `all_ids()`
- `find_engraving(engraving_id)`
- `validate()`

本阶段内容为：

| ID | 名称 | 原语 | 参数 |
|---|---|---|---:|
| `engraving_echo` | 回声 | `ECHO_ADJACENT` | 2 |
| `engraving_anchor` | 锚定 | `ANCHOR_DIE` | 4 |
| `engraving_bridge` | 桥接 | `BRIDGE_FORWARD` | 1 |
| `engraving_prism` | 棱镜 | `PRISM_PARITY` | 0 |

`amount=2` 的回声表示相邻点数除以二并向下取整；
`amount=4` 的锚定表示规则台通过后的固定奖励。

## 6. 骰子与刻印激活

`DieState` 扩展为同时保存：

- `id`
- `rolled_value`：本轮原始投掷值
- `value`：经过校准后供当前方案使用的有效点数
- `engraving_id`
- `engraved_face`

新骰子创建时 `rolled_value == value`。校准只修改 `value`。
卡牌点数修改仍由统一结算路径产生最终有效值，不改写 `rolled_value`。

刻印的本轮激活条件为：

1. 骰子的 `rolled_value == engraved_face`。
2. 骰子被分配到一张规则台。
3. 刻印 ID 能从 `EngravingCatalog` 解析。

校准不会改变本轮刻印是否已被投出。UI 必须同时显示原始投掷值、有效值变化和刻印激活状态，
避免玩家误以为校准改变了物理刻印面。

验证局只覆盖所选骰子的 `rolled_value`，令其等于所选刻印面；
其余五颗骰子继续消耗同一个 `RunRng`。覆盖是公开的阶段验证规则，
不作为正式区域遭遇能力。

## 7. `ResolutionContext` 与分阶段解析

新增不可变的 `ResolutionContext`，包含：

- 当前 `DealerDefinition`，可为空。
- `EngravingCatalog`。

每轮骰子的刻印 ID、刻印面和原始投掷值保存在 `RoundState.dice`；
跨遭遇的六骰持久配置只由 `IronAbacusSliceSession` 持有，并在创建新一轮时复制到
`DieState`。`ResolutionContext` 不保存第二份骰子状态。

上下文沿以下路径注入：

```text
IronAbacusSliceSession
  → ThreeRoundEncounterSession
  → SingleEncounterSession
  → RoundController
  → RoundActions / CardRules / RoundResolver
```

默认空上下文保持现有教学和阶段四行为。

刻印解析由有限的 `EngravingResolver` 服务承担，分为四个时机：

1. **动作校验**：锚定拒绝校准和点数修改牌。
2. **条件输入**：棱镜为奇偶条件提供双重标签。
3. **规则台通过后**：回声和锚定生成固定奖励。
4. **桌间传递**：桥接把待结算奖励送到当前方向中的下一张规则台。

庄家奖励在所有规则台和桌间事件之后执行。所有阶段都向同一
`ResolutionReport.events` 写入事件，预览和提交不得有第二套实现。

`ResolutionEvent` 增加 `effect_applied: bool`，默认值为 `true`：

- 实际应用的刻印事件设为 `true`，即使其数值增量为零。
- 缺少相邻骰、没有下一张台或目标规则无效等说明事件设为 `false`。
- `event_signature()` 包含该字段，确保预览和提交连同应用状态完全一致。

## 8. 铁算盘规则

铁算盘三轮累计目标为 `150`，成功不额外发放情报券。

每轮庄家奖励公式为：

```text
庄家奖励 = max(12 - 未分配骰数量 × 2, 0)
```

因此分配 `0..6` 颗骰子时，奖励依次为：

```text
0, 2, 4, 6, 8, 10, 12
```

“已分配”只表示骰子 ID 出现在任一规则台的分配数组中。
规则台是否满足条件不改变已分配数量。这样低价值骰仍需要占用有限槽位，
但不会通过隐藏惩罚或随机损失处理。

庄家事件固定在每轮事件列表末尾显示：

- 已分配骰数量。
- 未分配骰数量。
- 完整奖励。
- 扣减值。
- 本轮实际庄家奖励。

庄家失败摘要额外显示最后一轮未分配骰数量和因此损失的固定奖励。

## 9. 四种基础刻印

### 9.1 回声

激活骰所在规则台满足条件后：

1. 在该规则台的分配顺序中查找紧邻槽位。
2. 若左右都有相邻骰，取有效点数较高者。
3. 奖励为相邻有效点数除以 `2` 并向下取整。
4. 奖励作为独立事件加入当前规则台之后。

没有相邻骰时生成增量为 `0` 的说明事件。规则台不满足条件时不产生回声收益。

### 9.2 锚定

当原始投掷值命中刻印面时，该骰整轮处于锚定状态：

- 校准动作不能选择该骰。
- `ADJUST_DIE` 手法牌不能以该骰为目标。
- 拒绝发生在动作提交前，不消耗校准点、不打出手法牌、不写入撤销历史。
- 该骰所在规则台满足条件时增加 `4` 点固定奖励。

锚定不会阻止骰子分配、收回或规则台修改牌。

### 9.3 桥接

激活骰所在规则台满足条件后：

1. 按当前实际结算方向查找下一张规则台。
2. 建立一个待处理奖励，数值等于该骰经过校准和手法牌后的有效点数。
3. 下一张规则台也满足条件时，在其基础结果之后加入桥接奖励事件。

源规则台无效、目标规则台无效或当前方向没有下一张规则台时，
不增加解析值，并生成具体的零增量原因事件。

### 9.4 棱镜

激活骰进入奇偶条件验证时，同时提供“奇数”和“偶数”标签。

- 它可以让实际奇数通过 `ALL_EVEN` 条件。
- 它不改变实际点数、点数和、连续关系或最终得分。
- 即使实际点数本来就是偶数，也生成一条零增量激活事件，供验证局确认触发。

`RuleEvaluator` 的奇偶判断必须消费显式条件标签，不能在 UI 中伪造通过结果。

## 10. 完整流程

### 10.1 普通房与商店

1. 教学页点击“三轮试局”。
2. 创建 `IronAbacusSliceSession`，初始种子为 `20260726`。
3. 普通房使用现有三张规则台、目标 `100` 和十二张起始牌。
4. 成功获得 `2` 张情报券并进入现有替换商店。
5. 玩家可进行零至两次替换。
6. 离店时牌组和剩余情报券回写父级会话。

普通房失败保持现有同种子重试和返回教学路径。

### 10.2 铁算盘

离店摘要增加“挑战铁算盘”操作。进入时：

- 保存庄家边界快照。
- 使用继承的十二张牌重新洗牌。
- 继续使用同一随机流。
- 使用目标 `150`。
- 三轮均应用铁算盘奖励。

失败后可以：

- 从庄家边界同配置、同 RNG 状态重试。
- 返回教学。
- 完整重试整个切片。

### 10.3 刻印奖励

击败铁算盘后：

1. 使用同一 `RunRng` 打乱四种刻印 ID。
2. 展示前三种，顺序固定可复现。
3. 玩家选择一个候选。
4. 玩家选择 `d1..d6` 中一颗尚未刻印的骰子。
5. 玩家选择骰面 `1..6`。
6. 确认后在副本中安装，校验通过才原子提交。

本阶段只有一次安装机会。确认成功后不能返回改选，完整切片重试会清除安装结果。

### 10.4 刻印验证局

验证局：

- 只有一轮。
- 继续使用继承牌组。
- 不计算累计目标，不产生情报券，不进入商店。
- 所选骰子的原始投掷值固定为刻印面。
- 其他五骰继续使用共享随机流。
- 使用现有三张规则台。

正式结算后，系统检查事件列表中是否存在所选刻印 ID 的事件：

- 存在且 `effect_applied == true`：显示刻印来源、效果和最终牌组，阶段完成。
- 不存在，或只有 `effect_applied == false` 的说明事件：
  显示未触发原因，并允许从验证边界用同配置重试。

## 11. UI 与场景

### 11.1 新入口场景

新增：

- `scenes/run/iron_abacus_slice_screen.tscn`
- `scripts/ui/iron_abacus_slice_screen.gd`

它只负责：

- 绑定 `IronAbacusSliceSession`。
- 在普通房、商店、庄家、奖励和验证视图之间切换。
- 转发真实用户动作。
- 显示领域返回的状态和错误。

不在脚本中动态拼装整张页面。稳定层级和面板内容保存在 `.tscn`。

教学页“三轮试局”按钮改为进入该场景。现有
`three_round_run_screen.tscn` 保留为阶段四独立回归入口。

### 11.2 庄家显示

`SingleEncounterScreen` 左侧庄家区域增加唯一节点并绑定：

- 庄家名称。
- 庄家规则文本。
- 当前轮已分配骰数量。
- 当前预测庄家奖励。

默认教学继续显示镜面夫人的现有静态文案；外部会话可通过受控接口覆盖。

### 11.3 刻印奖励面板

新增场景化组件：

- `scenes/components/engraving_reward_panel.tscn`
- `scripts/ui/engraving_reward_panel.gd`

固定包含：

- 三个刻印候选槽。
- 六颗骰子选择按钮。
- 六个骰面选择按钮。
- 当前选择摘要。
- 规则文字和关联标签。
- 确认安装、返回查看和错误区域。

确认按钮只有在候选、骰子和骰面全部选择后启用。最终合法性仍由领域层判断。

### 11.4 骰子刻印反馈

`DieToken` 同时显示：

- 骰子 ID。
- 当前有效点数。
- 原始投掷值与调整箭头。
- 刻印名称或符号。
- 刻印面。
- “本轮激活”或“未激活”文字。

锚定骰作为非法点数修改目标时，必须显示具体原因，不能只取消高亮。
刻印的区分同时使用符号、名称和轮廓，不只依赖颜色。

## 12. 数据流

```text
教学入口
  → IronAbacusSliceSession 创建共享 RunRng
  → 普通房 ThreeRoundEncounterSession
  → ShopSession 原子替换
  → 回写牌组与情报券
  → 保存庄家边界 RNG 状态
  → 铁算盘 ThreeRoundEncounterSession
  → ResolutionContext 注入 DealerDefinition
  → RoundResolver 追加庄家事件
  → EngravingCatalog 四选三
  → 原子安装 engraving_id + engraved_face
  → 验证局注入 EngravingCatalog 与骰子配置
  → EngravingResolver 分阶段处理
  → 同一 ResolutionReport 用于预览与提交
  → 检查刻印事件并完成阶段
```

任何 UI 节点都不能直接写入骰子刻印字段、RNG 状态或跨阶段牌组。

## 13. 错误处理

- 庄家或刻印资源无效：阻止启动并列出路径、字段和期望值。
- 候选不属于本次三选一：拒绝安装。
- 骰子 ID 不存在：拒绝安装。
- 骰子已经有刻印：拒绝安装。
- 骰面不在 `1..6`：拒绝安装。
- 任一安装失败：候选、骰子配置和阶段状态全部保持不变。
- 锚定骰被校准或被点数牌选择：返回中文原因且不消耗资源。
- 重复接受同一正式报告：拒绝，不重复累计或转换阶段。
- 旧阶段报告在新阶段提交：拒绝并显示陈旧报告原因。
- RNG 边界快照缺失：阻止重试，不使用新随机状态替代。
- 验证局刻印未激活：不完成阶段，列出未分配、规则无效、无相邻骰或无桥接目标。
- 未知刻印 ID 出现在骰子状态：开发构建阻止进入遭遇，不静默忽略。

## 15. 完成标准

- 普通房商店替换后的牌组能进入铁算盘挑战。
- 铁算盘三轮目标固定为 `150`，每轮庄家奖励完全公开。
- 六骰分配数量与庄家奖励公式一致。
- 玩家可从四种刻印的三个确定性候选中选择一个。
- 刻印安装到真实骰子的真实骰面，失败时保持原状态。
- 四种刻印都通过统一解析路径生成独立事件。
- 验证局必定让所选刻印面出现，但只有合法分配和规则结果才能完成对应效果。
- 预测与正式提交的总计和事件签名完全一致。
- 同种子可复现完整子项目随机结果。
- 庄家边界重试不会丢失普通房商店结果。
- UI 不计算庄家奖励、刻印效果或完成状态。
- 现有教学与阶段四行为没有回归。
- 自动化、真实输入和双分辨率可视验收全部通过。
- 设计与实施计划只暂存，所有代码提交显式排除文档和 `project.godot`。
