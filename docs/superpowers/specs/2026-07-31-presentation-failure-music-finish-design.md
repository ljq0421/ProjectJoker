# 表现、失败复盘与音乐收口设计规格

> 文档日期：2026-07-31
> 前置阶段：正式十八类规则池、差异化活动与奖励、远征复玩配置
> 状态：阶段范围已确认
> 文档边界：只暂存，不进入阶段代码提交

## 1. 目标

D 阶段负责把已经形成的玩法循环变成可读、可复盘、可辨认且声音完整的产品表面：

1. 失败时解释可证实的损失来源，而不只显示累计值和差值；
2. 修复正式区域中浮动返回按钮遮挡标题和商店顶栏的问题；
3. 让金线回廊、反照牌厅和无面中枢在真实玩法页拥有不同视觉身份；
4. 接管并完成当前工作区的程序化音乐、Music 总线和设置持久化；
5. 保持确定性解题、无永久数值成长和现有存档语义不变。

## 2. 不包含

- 不增加新区域、房间、规则、卡牌、刻印或挑战词条；
- 不重新平衡目标值和奖励；
- 不把建议描述为确定的最优解；
- 不加入老虎机、筹码、下注、概率返利或追损语义；
- 不宣称自动化验证等同于十局真人体验或主观音乐试听；
- 不提交此前 A/B/C 的六份设计文档。

## 3. 失败复盘

### 3.1 结构化事实

`ResolutionReport` 增加不参与计分的诊断字段：

- `rule_failures`：规则台 ID、显示名、失败原因和该台使用骰数；
- `missed_effects`：未触发的桥接、回声、刻印或条件奖励说明；
- `assigned_dice` / `unassigned_dice`：所有正式遭遇均记录，不再只记录庄家；
- `dealer_reward_lost`：庄家固定奖励的可证实损失。

结算总分、事件顺序和 RNG 不因诊断字段变化。

### 3.2 跨轮复盘

新增纯逻辑 `FailureReviewBuilder`，输入已提交报告、累计目标和庄家标记，输出：

- 目标差值；
- 得分最低轮次及其分数；
- 去重后的失效规则；
- 未分配骰总数；
- 庄家奖励损失；
- 最多三条建议。

建议按公开优先级生成：

1. 有未分配骰时，先建议完成分配；
2. 有失效规则时，先建议满足首个失效规则；
3. 有未触发效果时，提示检查相邻目标、结算方向或条件；
4. 最后说明仍需补足的目标差值。

这些建议是基于公开结果的启发式提示，不声称找到最优操作。

### 3.3 界面

失败摘要分成“结果”“主要损失”“下次可尝试”三个区域。事实与建议使用不同标题，不混写。失败复盘支持自动换行，并在 1280×720、1600×900、1920×1080 下完整落在视口内。

## 4. 顶部导航

正式 `AreaRunScreen` 保留共享“返回主页面”按钮，但为嵌入的遭遇和商店页面预留顶部契约栏：

```text
┌──────────────────────────────────────────────────────────────┐
│ 返回主页面                         区域契据 / 当前阶段        │
├──────────────────────────────────────────────────────────────┤
│ 子页面自己的标题、目标、情报券与设置入口                     │
│                                                              │
│ 玩法内容                                                     │
└──────────────────────────────────────────────────────────────┘
```

按钮不再浮在子页面标题上。设置按钮保留右上角，返回按钮位于左上角，子页面内容从预留高度之后开始。

## 5. 视觉方向

### 5.1 主题与读者

主题是“可核验的梦境契据”，面向需要在高信息密度下快速区分规则环境的策略玩家。页面的首要任务是让玩家一眼知道自己身处哪个区域，并能继续读清规则。

### 5.2 色彩令牌

共享底色继续使用 Dream Glass，不重做全局 Theme。区域只覆盖局部强调色与背景图式：

| 区域 | 主色 | 辅色 | 深底 | 语义 |
|---|---|---|---|---|
| 金线回廊 | `#E7B84B` | `#55E7C5` | `#07121C` | 账线、校验、并行路径 |
| 反照牌厅 | `#79D8FF` | `#B57AFF` | `#090B24` | 镜轴、折返、回声 |
| 无面中枢 | `#FF71B7` | `#65EEDB` | `#15091D` | 三席、索引、无名协议 |

正文继续使用现有中文字体和字号体系，避免为装饰引入缺字风险。区域英文眉题只作为短标签，不替代中文信息。

### 5.3 布局与标志

记忆点只放在一处：庄家侧栏顶部的“契据印记”。

- 金厅：三根平行账杆和可移动算珠；
- 镜厅：沿中轴对称的折光面；
- 无面中枢：空心面具与三个公开席位节点。

背景使用同一语义的低对比程序化线条。卡牌、规则台和按钮继续使用共享 Dream Glass，避免每区重做整套控件而降低学习迁移。

### 5.4 自检

该方案不采用通用紫色渐变作为区域差异；每种图式直接来自对应区域机制。视觉风险集中在一个庄家印记和低对比背景，其他界面保持克制。

## 6. 音乐

### 6.1 资产与来源

保留当前三首确定性程序化 WAV：

- `glass_antechamber.wav`：主菜单；
- `masked_table.wav`：路线、商店、档案、奖励与旅程；
- `loaded_dice.wav`：正式遭遇与庄家。

生成器只使用 Python 标准库、数学振荡器、确定性噪声和 WAV 写入。`manifest.json` 保存参数与 SHA-256；`PROVENANCE.md` 说明无第三方采样，但不替代发行地区的最终法律审查。

### 6.2 运行时

`MusicService` 继续使用两个播放器交叉淡入淡出。除场景路径自动识别外，正式区域必须在内部阶段切换时显式请求：

- 路线、商店、奖励、区域完成：`journey`；
- 普通遭遇、庄家：`encounter`；
- 返回主菜单：`menu`。

重复请求相同上下文不得重启曲目。

### 6.3 设置

设置页增加独立背景音乐音量和静音项：

- 默认约 25%，低于 UI 与玩法音效；
- 旧设置文件缺少音乐字段时使用默认值；
- 滑动、静音、恢复默认和重启后持久化；
- 音乐滑杆不播放 UI 预听音，直接调整正在播放的音乐。

## 7. 验收

- 失败摘要能显示结构化事实和最多三条建议；
- 失败诊断不改变任何正式计分、RNG 或存档结果；
- 返回按钮与遭遇、商店标题在三种目标分辨率下不重叠；
- 三个区域的背景图式、颜色和庄家印记可由截图区分；
- 路线/商店/遭遇的音乐上下文在同一 `AreaRunScreen` 中真实切换；
- 三首 WAV 通过资产集合、格式、峰值、哈希、来源和完全复现校验；
- 音乐设置通过旧文件迁移、音量、静音、恢复和持久化测试；
- 全量测试、三区输入/布局/端到端、双分辨率截图和非 headless 音频运行时检查通过；
- 真人十局和主观试听仍作为人工验收项明确列出。
