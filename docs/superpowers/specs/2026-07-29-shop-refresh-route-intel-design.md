# 《六面诡局》商店付费刷新与路线情报设计规格

> 项目：Project Joker
> 日期：2026-07-29
> 上位规格：`2026-07-24-six-sided-rulebreakers-design.md`
> 前置阶段：十八种基础规则台目录与规则档案室
> 状态：对话设计已确认，待书面规格审阅

## 1. 目标

本阶段补完每个正式地区两家商店中的两项确定性服务：

1. 玩家每家商店可以支付 1 张情报券，把当前三张候选整批刷新为三张本店未展示过的新候选。
2. 玩家每家商店可以支付 1 张情报券，提前查看离店后的完整公开规则：
   - 第一家商店预览第二组路线中的两个房间。
   - 第二家商店预览本地区庄家。
3. 刷新、情报和换牌共同使用情报券，形成公开且可计算的资源取舍。
4. 所有未来内容在开店时确定；购买服务只解锁信息或推进预排候选，不现场改变未来随机结果。

本阶段继续保持“公开信息、预演、约束选择和确定性策略”的玩法定位。
不增加重掷、下注、概率触发、隐藏补偿或随机奖励。

## 2. 已确认口径

- 换牌价格：1 张情报券。
- 整批刷新价格：1 张情报券，每家商店最多一次。
- 路线或庄家情报价格：1 张情报券，每家商店最多购买一次。
- 刷新后当前三张候选全部退场，本店内不再返回。
- 刷新成功后必须出现三张合法且本店从未展示过的新候选。
- 被换出当前牌组的旧牌仍属于地区市场，可以在之后的商店中成为回购候选。
- 第一家商店的情报是完整的第二组路线预览。
- 第二家商店的情报是完整的庄家规则预览。
- 庄家情报不提前生成或泄露未来骰面、手牌和结算结果。
- 现有房间奖励、目标、固定种子、牌面数值和 40 张卡牌目录不重平衡。

## 3. 阶段边界

### 3.1 包含

- `ShopSession` 的一次性整批刷新与情报购买。
- 地区市场、稳定候选优先序和旧牌回购。
- 第一家商店的第二路线组快照。
- 第二家商店的庄家规则快照。
- 金线回廊、反照牌厅和无面中枢的两家正式商店。
- 商店服务记录及区域完成摘要。
- 领域、确定性、真实输入、布局和三个地区端到端验证。

### 3.2 不包含

- 新卡牌、新规则台、新刻印或新庄家。
- 房间目标、奖励、固定骰面或固定种子的平衡调整。
- 第三次刷新、刷新价格成长或服务折扣。
- 购买后改写路线候选、庄家日程或限制选项。
- 未来骰面、手牌或推荐解法预告。
- 连续三区远征、跨区域状态继承或跨启动存档。
- 结算动画、无障碍扩展或叙事内容。

本阶段提供稳定 ID、不可变快照和结构化服务记录，供下一阶段的连续三区远征复用，
但不提前实现其状态机或存档。

## 4. 现有基线

当前工程已经具备：

- `AreaRunSession`：两个普通房、两家商店、庄家和刻印奖励的正式区域流程。
- `ShopSession`：1 券购买候选牌并原子替换十二张牌组。
- `RunRng`：可注入、可快照和恢复的共享确定性随机流。
- `RoomDefinition`、`AreaDefinition` 和三个地区目录。
- `RouteChoicePanel`：公开展示两个房间的目标、奖励、规则台和牌组呼应。
- 铁算盘、镜面夫人和无面主人的庄家定义。
- 无面主人的三轮公开日程和两种最终限制。
- 40 张稳定 ID 的手法牌目录。

当前 `AreaRunSession.open_shop()` 只从 `AreaDefinition.shop_offer_ids`
中排除当前牌组后抽取三张候选；`ShopSession` 不持有 RNG 或未来路线资料。
第一次离店时才生成第二组路线顺序。实现本规格时必须移动“未来内容确定”的时机，
但不得让是否购买情报影响实际路线或庄家。

## 5. 地区市场

### 5.1 定义

区域开始时创建一次不可变的地区市场 ID 集合：

```text
地区市场 = 区域入口时的十二张牌组 ID ∪ AreaDefinition.shop_offer_ids
```

该集合在区域内两家商店之间保持不变。牌组替换只改变哪些牌位于当前十二张牌组，
不从地区市场删除任何牌。

当前独立地区的市场规模为：

- 金线回廊：12 张入口牌组 + 6 张商店牌 = 18 张。
- 反照牌厅：12 张入口牌组 + 6 张商店牌 = 18 张。
- 无面中枢：12 张入口牌组 + 16 张商店牌 = 28 张。

三个地区的入口牌组与各自商店候选池当前没有重复 ID。
内容校验仍须使用集合运算验证，不能依赖这一事实永远成立。

### 5.2 不变量

- 当前牌组始终恰好 12 张且 ID 唯一。
- 当前牌组中的每张牌都属于地区市场。
- 商店候选不得位于当前牌组。
- 同一家商店的已展示 ID 不得再次出现。
- 换下的旧牌留在地区市场，之后可以回购。
- 购买、回购和刷新均不改变地区市场本身。

金线回廊和反照牌厅的市场恰好有 6 张牌位于当前牌组之外。
即使玩家购买候选，换下的旧牌也同步进入牌组之外，因此场外数量保持为 6。
在本店已展示的三张中，已购买的牌进入牌组；未购买的牌仍被“本店已展示”排除。
无论购买 0 至 3 张，刷新时都至少存在三张合法候选。

## 6. 确定性候选优先序

### 6.1 开店预排

每次开店时，`AreaRunSession` 使用共享 `RunRng` 对完整地区市场 ID
生成一个稳定优先序，并把优先序副本传入 `ShopSession`。

`ShopSession` 按优先序扫描：

1. 跳过当前牌组中的牌。
2. 跳过本店已经展示过的牌。
3. 选取前三张合法牌。

第一次扫描生成首批候选，并把三张 ID 记入本店已展示集合。

### 6.2 刷新

`refresh_offers()` 不调用 RNG，只沿既有优先序重新扫描当前状态：

1. 验证当前处于可刷新状态。
2. 验证余额不少于 1。
3. 在副本中寻找三张不在当前牌组且本店未展示的牌。
4. 找不足三张则整体失败。
5. 成功后扣除 1 券、替换整批候选、追加已展示 ID、标记本店已刷新。

因为购买会改变当前牌组，刷新候选可以包含刚被换下的旧牌。
相同种子和相同购买、刷新操作序列必须得到相同结果。
刷新是否发生不得改变后续路线、遭遇骰面或手牌的 RNG 状态。

### 6.3 已售候选

购买后现有候选牌继续显示售出状态，直到玩家刷新或离店。
刷新时三张旧候选全部退场，包括已经售出的候选。
刷新后的候选拥有独立的售出状态，但本店刷新次数不重置。

## 7. 未来情报快照

### 7.1 通用模型

新增只包含稳定内容 ID 和不可变标量的情报快照。
快照不持有 UI 节点，不从 UI 反查领域状态。

快照类型至少区分：

- `ROUTE_PAIR`
- `DEALER`

`ShopSession` 可以持有快照，但只有 `intel_unlocked == true` 时才允许 UI 读取展示数据。
情报购买不重新建立快照。

### 7.2 第一家商店：路线快照

第一次开店的原子准备过程包含：

1. 验证第二组路线恰好包含两个不同且有效的房间。
2. 使用共享 RNG 生成并保存第二组路线顺序。
3. 把两个房间稳定 ID 写入路线快照。
4. 离店后直接把这两个 ID 设为实际 `route_ids`，不再次洗牌。

路线情报展示：

- 房间名称和说明。
- 三轮累计目标。
- 成功情报券奖励。
- 房间标签。
- 三张规则台的名称、条件、参数、骰位和系数。
- 与当前牌组匹配的牌组呼应。

规则快照和路线顺序不可变。牌组呼应是展示派生值，每次打开情报层时使用
当前 `ShopSession.deck_ids` 重新计算。

### 7.3 第二家商店：庄家快照

第二次开店建立庄家快照，不提前启动 `ThreeRoundEncounterSession`，
也不消费庄家遭遇的骰面或手牌随机数。

通用庄家情报展示：

- 庄家名称。
- 三轮累计目标。
- 庄家固定机制和奖励、惩罚规则。
- 三轮使用的规则台、条件参数、骰位和系数。
- 每轮解析方向。

铁算盘和镜面夫人的固定遭遇明确标注三轮沿用同一组规则。
镜面夫人额外展示逆序和镜像副本机制。

无面主人额外展示：

- 三轮各自的规则台日程。
- 每轮解析方向。
- 第二轮结束后出现的两种公开最终限制。
- 限制对第三轮的准确影响。

情报不展示未来骰面、手牌、自动推荐操作或结算总分。

## 8. 商店领域接口

### 8.1 `ShopSession` 状态

在现有状态基础上新增：

- `market_priority_ids`
- `shown_offer_ids`
- `refresh_used`
- `intel_snapshot`
- `intel_unlocked`
- `service_records`

常量：

- `CARD_PRICE := 1`
- `REFRESH_PRICE := 1`
- `INTEL_PRICE := 1`

### 8.2 `refresh_offers()`

成功结果：

- 扣除 1 张情报券。
- 替换全部三个候选。
- 新候选加入本店已展示集合。
- `refresh_used = true`。
- 记录一次刷新服务。
- 清空 `last_error`。

失败结果不得改变任何领域状态。

### 8.3 `purchase_intel()`

成功结果：

- 扣除 1 张情报券。
- `intel_unlocked = true`。
- 记录一次情报服务。
- 清空 `last_error`。

重复购买、余额不足或快照无效时整体失败。
已解锁后查看情报不调用 `purchase_intel()`，不再扣券。

### 8.4 服务记录

新增结构化服务记录，至少包含：

- 商店序号。
- 服务类型：刷新或情报。
- 花费。
- 情报类型：路线或庄家；刷新记录不填。

换牌继续使用现有 `ShopPurchaseRecord`。
`AreaRunSession.leave_shop()` 原子复制两类记录，区域完成摘要分别展示。

## 9. 区域会话集成

### 9.1 区域开始

`AreaRunSession.start()` 在提交初始状态前：

1. 建立地区市场。
2. 验证所有 ID 已知且唯一。
3. 验证入口牌组恰好 12 张并完全属于市场。
4. 验证当前牌组之外至少有 6 张合法候选。

验证失败不得开始区域或消费 RNG。

### 9.2 开店

`open_shop()` 的原子准备顺序为：

1. 快照 RNG。
2. 验证当前普通房已经成功。
3. 验证地区市场和当前牌组。
4. 为完整地区市场生成本店优先序。
5. 建立下一节点情报快照。
6. 创建并验证 `ShopSession`。
7. 全部成功后提交 `shop_session` 和预定下一路线。

任何步骤失败时恢复 RNG，并保持阶段、牌组、余额、记录和路线不变。

### 9.3 离店

第一次离店：

- 原子接收牌组、余额、换牌记录和服务记录。
- 使用开店时保存的第二组路线 ID。
- 不重新洗牌。
- 进入 `ROUTE_CHOICE`。

第二次离店：

- 原子接收同样的商店结果。
- 使用快照对应的同一庄家定义创建庄家遭遇。
- 不因是否购买情报而改变庄家创建顺序或内容。

## 10. 商店界面

### 10.1 稳定结构

`shop_screen.tscn` 增加：

- 刷新状态标签。
- 情报状态标签。
- `RefreshOffersButton`。
- `PurchaseIntelButton`。
- 刷新 `ConfirmationDialog`。

稳定布局和文案容器保存在 `.tscn`。
脚本只绑定状态、转发领域操作、刷新选择和处理信号。

### 10.2 状态与操作

- 顶部持续显示情报券余额。
- 明确显示 `刷新：可用/已使用`。
- 明确显示 `路线情报：未购/已购` 或 `庄家情报：未购/已购`。
- 刷新按钮文字为 `整批刷新（1 情报券）`。
- 情报按钮未购时显示购买文案，已购后改为 `查看已购情报`。
- 刷新确认框说明当前三张候选会永久退出本店。
- 刷新成功后清空候选牌和旧牌选择，避免旧选择误购。
- 情报购买成功后立即打开情报层。
- 玩家可以关闭情报层、继续换牌、再次免费查看或直接离店。
- 余额不足、重复服务或内容错误显示具体中文原因。

按钮状态、文字和错误原因共同表达状态，不只依赖颜色。

## 11. `ShopIntelPanel`

新增只读全屏覆盖层 `ShopIntelPanel`，可绑定路线或庄家快照。
覆盖层可见时使用 `MOUSE_FILTER_STOP` 阻止背后商店输入。

### 11.1 路线模式

两个房间并排展示，信息与正式 `RouteChoicePanel` 一致，但：

- 不显示或不启用路线选择按钮。
- 标题明确写为 `已购路线情报`。
- 提供 `返回商店`。
- 牌组呼应使用当前商店牌组实时派生。

路线展示格式应复用共同格式化逻辑，避免预览与正式路线面板对同一规则
生成不同文案。

### 11.2 庄家模式

庄家模式展示：

- 庄家身份、目标和固定机制。
- 三轮规则卡。
- 方向、规则条件和参数。
- 特殊机制的准确触发口径。
- 无面主人的两种最终限制。
- `返回商店`。

固定结构保存在场景中。脚本根据快照绑定三轮内容，
不在运行时拼装整张页面层级。

## 12. 区域完成摘要

现有区域完成摘要在两次商店记录中分别展示：

- 换入牌、换出牌和价格。
- 是否使用整批刷新及花费。
- 是否购买路线或庄家情报及花费。
- 两家商店各自总支出。

最终情报券余额仍直接来自 `AreaRunSession`。
摘要不得用余额差值反推交易记录。

## 13. 错误处理与原子性

以下操作必须拒绝并返回具体中文原因：

- 地区市场包含未知或重复 ID。
- 当前牌组不属于地区市场。
- 当前牌组之外不足 6 张合法候选。
- 候选优先序缺失、重复或不覆盖地区市场。
- 首批候选不足三张。
- 刷新后新候选不足三张。
- 本店已经刷新。
- 本店已经购买情报。
- 情报券不足。
- 情报快照类型或内容无效。
- 第一家商店缺少两个有效的第二路线房间。
- 第二家商店缺少庄家、遭遇、日程或限制资料。

失败操作必须证明以下快照不变：

- RNG 状态。
- 区域阶段、房间序号和预定路线。
- 地区市场和当前牌组。
- 商店候选、已展示集合和售出集合。
- 情报券。
- 刷新与情报使用状态。
- 换牌与服务记录。
- 情报快照。

## 14. 测试与验收

### 14.1 商店领域测试

- 三种价格均为 1。
- 首批候选恰好三张且不在当前牌组。
- 刷新扣 1 券并产生三张本店未展示的新候选。
- 第二次刷新整体失败且状态不变。
- 余额不足刷新整体失败。
- 购买 0、1、2、3 张后刷新都仍有三张合法候选。
- 先刷新再购买与先购买再刷新均保持十二张唯一牌组。
- 被换下的旧牌可以按优先序成为刷新或第二家商店候选。
- 本店旧候选不会在刷新后返回。
- 情报购买扣 1 券并只解锁一次。
- 已购情报可以重复读取且不再扣券。
- 未购时领域层拒绝读取情报展示数据。
- 所有失败保持完整商店快照不变。

### 14.2 地区会话测试

金线回廊、反照牌厅和无面中枢分别覆盖：

- 两家商店均可换牌、刷新和购买情报。
- 第一家商店情报与离店后实际路线 ID、顺序和内容一致。
- 第二家商店情报与实际庄家 ID、目标、机制、日程和限制一致。
- 是否购买或查看情报不改变实际未来内容。
- 刷新不改变离店后的 RNG 状态。
- 离店正确复制换牌与服务记录。
- 重新开始区域清除市场、商店状态、服务记录和预定路线并完整复现。

### 14.3 确定性测试

相同种子和相同操作序列必须复现：

- 两家商店的首批候选。
- 刷新候选。
- 被换下旧牌的回购顺序。
- 第二组路线顺序。
- 庄家规则快照。
- 后续遭遇骰面、手牌和事件签名。

购买情报、重复查看情报和关闭情报层均不得消费 RNG。
刷新只使用开店时的优先序，不得在点击时消费 RNG。

### 14.4 UI 合同与真实输入

真实鼠标路径覆盖：

1. 进入正式地区并完成第一个普通房。
2. 进入第一家商店。
3. 打开并取消一次刷新确认。
4. 再次确认刷新并看到三张新候选。
