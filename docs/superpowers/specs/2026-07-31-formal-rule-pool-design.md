# 《六面诡局》正式远征十八类规则池设计规格

> 文档日期：2026-07-31
> 上位规格：`2026-07-24-six-sided-rulebreakers-design.md`
> 前置实现：十八项基础规则台目录、三区连续远征
> 状态：设计已确认
> 文档边界：只暂存，不进入阶段代码提交

## 1. 已确认决策

- 十八类基础规则全部进入正式房间或庄家内容池。
- 单局不强制遇到全部十八类；路线选择保留内容差异。
- 不增加区域、房间、遭遇轮数或远征长度。
- 重编现有十二个普通房与三名庄家的规则组合。
- 继续保持规则、方向、代价和结果在提交前完全公开。
- 不增加隐藏随机、概率奖励、永久倍率或局外数值成长。

## 2. 产品目标

解决“目录中有十八类规则，但正式远征只重复三类规则”的内容断层。完成后：

- 正式内容池引用十八类规则模板中的全部十八类。
- 三个区域拥有明确的规则身份和难度递进。
- 同一路线节点的二选一产生不同解题方式，而不只是不同目标数值。
- 完整远征仍由九场遭遇、最多二十七轮组成。

## 3. 区域身份

### 3.1 金线回廊：点数与基础关系

金线回廊负责教授公开阈值、奇偶、集合和基础序列：

| 房间 | 左轨 | 中轨 | 右轨 |
|---|---|---|---|
| 精确步阶 | 精确总和 | 连续数列 | 最低总和 |
| 偶数分流 | 全偶 | 同奇偶 | 最高总和 |
| 窄幅账页 | 区间总和 | 固定差值 | 全奇 |
| 并行校核 | 全部不同 | 精确总和 | 全部同点 |
| 铁算盘 | 最低总和 | 精确总和 | 最高总和 |

本区不使用扭曲台，先建立条件判断和骰子分配基础。

### 3.2 反照牌厅：位置与扭曲

反照牌厅负责教授槽位顺序、镜像、方向和跨台事件：

| 房间 | 左轨 | 中轨 | 右轨 |
|---|---|---|---|
| 逆序校场 | 严格降序 | 反向台 | 严格升序 |
| 双影账页 | 镜像排列 | 精确总和 | 全部同点 |
| 回声桥 | 回声台 | 桥接台 | 固定差值 |
| 对称账页 | 指定槽位 | 镜像排列 | 反向台 |
| 镜面夫人 | 回声台 | 桥接台 | 指定槽位 |

桥接台始终位于中轨。镜面夫人的公开右向左结算、镜像手法牌与规则台扭曲共同进入统一预演。

### 3.3 无面中枢：跨类别组合

无面中枢混合四类规则，并让最终限制改变操作优先级：

| 房间 | 左轨 | 中轨 | 右轨 |
|---|---|---|---|
| 交叉档案 | 区间总和 | 桥接台 | 严格降序 |
| 反向索引 | 反向台 | 指定槽位 | 全部不同 |
| 独手议程 | 最低总和 | 回声台 | 全部同点 |
| 三席协议 | 全奇 | 固定差值 | 最高总和 |
| 无面主人·正面 | 精确总和 | 同奇偶 | 严格升序 |
| 无面主人·反面 | 反向台 | 桥接台 | 严格降序 |
| 无面主人·无面 | 指定槽位 | 回声台 | 镜像排列 |

第三轮仍应用玩家公开选择的“独手裁定”或“三席到场”限制。

## 4. 参数与平衡原则

- 普通房三轨总骰位固定为六。
- 点数与关系台系数使用 `2..5`。
- 扭曲台系数低于同区条件台，避免事件复制形成失控倍率。
- 金线回廊目标保持入门区间，反照牌厅强调方向和位置，无面中枢强调组合。
- 先保留当前区域目标阶梯，再通过固定种子与可达性检查调整异常目标。
- 每个普通房至少存在两种让两张或以上规则台得分的确定性分配。
- 不要求单轮三台全过；区域目标通过三轮累计完成。

## 5. 路线差异门

- 同一组二选一房间的规则模板集合不得相同。
- 每个选项至少包含一个对方没有的规则类别或扭曲语义。
- 路线说明必须展示模板名称、参数、目标、奖励和当前牌组协同标签。
- 路线情报服务继续展示真实的未来房间和庄家规则。

## 6. 存档与兼容

- 不改变内容 ID、区域 ID、房间 ID、庄家 ID、阶段枚举或存档版本。
- 边界存档继续只保存稳定 ID 和状态，不保存规则资源节点路径。
- 旧检查点引用相同房间 ID 时加载新的规则编排；本阶段不支持旧规则布局回放。
- 预演与正式提交继续共享 `RoundResolver` 和统一事件列表。

## 7. 验收

- 正式十二个房间和三名庄家合计引用全部十八类模板。
- 每区至少引用六类不同模板。
- 每组路线二选一模板签名不同。
- 每个普通房通过内容校验和多台可达性检查。
- 固定种子的三区端到端流程通过。
- 商店未来情报与进入后的实际规则完全一致。
- 1280×720 与 1920×1080 下新规则文案、参数和槽位无裁切。
- 真实鼠标完成路线选择、指定槽位放置、交换、提交和返回。
- 全量测试通过，日志无 `SCRIPT ERROR|Failed to load script`。
