# 《六面诡局》垂直切片设计规格

> 项目代号：Project Joker  
> 文档日期：2026-07-24  
> 引擎：Godot 4.6.1  
> 目标平台：PC 横屏单机  
> 单局时长：30–45 分钟

## 1. 产品定位

《六面诡局》是一个以骰子分配、确定性规则修改和小型牌组构筑为核心的 Roguelike 策略游戏。玩家被困在一座不断重写自身规则的梦境赌场中，需要把六颗骰子分配到三张规则台，再用扑克牌形态的“手法牌”修改骰值、条件和结算顺序，逐层破解赌场。

游戏参考《小丑牌》“用熟悉规则承载构筑、逐关提高目标、简单组件产生复杂连锁”的设计方法，但不保留传统扑克出牌或牌型计分。其核心差异是：

- 操作对象是六颗骰子和三个并列的空间区域。
- 扑克牌是主动使用的规则修改器，不组成传统牌型。
- 主要决策是骰子分配、操作顺序和桌间联动。
- 所有规则公开、所有效果确定执行、所有结算可提前验证。

### 1.1 设计目标

1. 初始投骰制造问题，玩家通过计算和有限资源解决问题。
2. 每轮至少提供两条有意义的调整与分配路径。
3. 构筑改变玩家解决规则的方式，而不只是提高固定倍率。
4. 失败能够被解释为具体决策或构筑问题，而不是“运气不好”。
5. 在 1920×1080 的 PC 界面中同时清楚展示规则、操作对象和完整结算轨迹。

### 1.2 非目标

垂直切片不包含以下内容：

- 传统德州扑克、五张牌牌型或完整 52 张牌玩法。
- 下注、加注、借贷、追损、随机没收资产或现实货币赌博。
- 多人模式、排行榜、Steam 平台功能或每日挑战。
- 多角色、永久数值成长、完整剧情战役或移动端适配。
- 依赖触发概率的卡牌效果。

## 2. 单局结构

一局由三个区域组成，每个区域包含两个普通规则房和一个庄家房，共九场遭遇。每场遭遇固定为三轮，因此完整单局最多经历二十七轮。

进入普通规则房前，玩家从两组完全公开的房间规则和奖励中选择一组。每个普通房结束后进入商店。击败庄家后，玩家从三个稀有手法牌或骰面刻印奖励中选择一个，然后进入下一区域。

三个区域的功能为：

1. **金线回廊**：教授点数、关系和分配规则，庄家为“铁算盘”。
2. **反照牌厅**：引入桌间联动和结算顺序，庄家为“镜面夫人”。
3. **无面中枢**：组合已有规则并要求临场适应，庄家为“无面主人”。

每场遭遇要求玩家在三轮内累计达到公开的“解析目标”。失败时本局结束。普通房还提供一个公开的“精解条件”，例如本场不使用重投、三张规则台都恰好满足条件或不产生无效骰。完成精解条件可获得商店使用的“情报券”。

解析值与情报券彼此独立。获得高解析值不会自动带来更多购买力，避免领先构筑同时扩大分数和经济优势。

## 3. 单轮流程

每轮按以下顺序执行：

1. 展示三张规则台、庄家效果、本轮解析目标进度和完整条件。
2. 投掷六颗标准六面骰。
3. 从十二张手法牌组成的牌组中抽取四张。
4. 玩家拥有两个“校准点”；每个校准点可令一颗骰子确定性地增加或减少 1，点数不能越过 1 或 6。
5. 玩家可打出最多两张手法牌。
6. 玩家将骰子分配到三张规则台。每颗骰子只能使用一次，允许保留未分配骰。
7. 确认前可任意移动骰子、收回尚未结算的手法牌或撤销操作。
8. 右侧结算轨迹实时模拟当前方案。
9. 玩家确认后，系统按当前结算方向依次处理规则台、桌间效果和庄家规则。
10. 本轮所有未使用手牌进入弃牌堆，进入下一轮。

每场遭遇开始时重新洗牌。牌组固定为十二张，每轮抽四张，因此三轮内会看到牌组中的全部十二张，但出现顺序不固定。

## 4. 规则台与计分

每张规则台由四项数据组成：

- **骰位数量**：需要或最多可放置的骰子数量。
- **通过条件**：决定当前分配是否合法。
- **收益系数**：条件越严格，系数通常越高。
- **附加效果**：通过或失败时对本桌、相邻桌或结算顺序产生的确定性影响。

规则台基础公式为：

`规则台结果 = 已分配骰子的点数总和 × 收益系数 + 固定奖励`

手法牌、刻印和庄家规则在结算轨迹中依次修改该结果。游戏不设置可无限增长的全局倍率；爆发主要来自重复结算、相邻传递和条件重写。

### 4.1 规则台类别

- **点数台**：总和等于、高于、低于或处于公开区间。
- **关系台**：相同点数、连续点数、相同奇偶或固定差值。
- **位置台**：要求骰子按升序、降序、镜像或指定槽位放置。
- **扭曲台**：改变相邻台、结算方向或骰位连接方式。所有后果在确认前显示，不承担隐藏风险。

垂直切片包含十八张基础规则台定义。房间通过组合基础定义、数值参数和庄家修饰生成具体遭遇。

### 4.2 结算顺序

默认从左到右结算。手法牌或庄家可公开反转方向、重复某张台或在相邻台之间传递数值。系统必须生成逐项事件列表，例如：

1. 右侧规则台通过，获得 10。
2. “反相”重复右侧规则台，增加 10。
3. 中央规则台通过，获得 12。
4. 左侧规则台通过，获得 18。
5. 本轮合计 50。

界面预测和正式提交必须使用同一份事件列表生成逻辑。

## 5. 手法牌

手法牌使用扑克牌的花色、点数、构图和尺寸，但每张牌拥有独立名称与规则文字。垂直切片制作四十张效果牌，平均分布到四种花色。它们不要求组成一副完整的标准扑克牌；花色承担稳定的机制语义，牌面点数和人头牌用于表达强度与稀有度。

- **梅花**：修改、交换、冻结、复制或重新生成骰值。
- **红桃**：撤销、回收、保护和失误补偿。
- **方片**：情报券、商店替换和长期资源效率。
- **黑桃**：提高条件严格度、复制结算或重写顺序；效果强，但代价完全公开且确定。

手法牌可放在三个目标类型上：

- **骰子**：影响一个或多个骰子的点数或状态。
- **规则台**：修改该台的条件、系数或结算次数。
- **桌间槽**：连接两张相邻规则台，传递、复制或交换结果。

每轮最多打出两张手法牌。新牌不能扩大牌组容量；在商店获得新牌时，必须替换牌组中的一张旧牌。牌组编辑界面必须同时显示新旧牌的目标类型、实际数值和与当前构筑的关联标签。

## 6. 骰面刻印

玩家始终使用六颗标准六面骰。击败庄家后，可选择在某颗骰子的一个指定面上添加刻印。刻印只有在该面朝上且骰子被分配后生效。

垂直切片包含十二种刻印，分为以下类型：

- **回声**：复制相邻骰子的部分点数或标签。
- **锚定**：该骰不能被再次修改，但提高所在规则台的固定奖励。
- **桥接**：令所在规则台视为与隔壁台相连。
- **棱镜**：在公开条件下改变该骰的奇偶、位置或关系标签。

每颗骰子最多拥有一个刻印，每局最多获得两个刻印。刻印选择必须指定实际骰子与实际骰面，不能只作为抽象的全局被动效果。

## 7. 庄家挑战

庄家效果用于检验不同策略能力，不随机封禁整个花色或构筑。

### 7.1 铁算盘

- 六颗骰子必须全部被分配，才能获得本轮完整解析值。
- 未分配骰不会随机处罚，而是按公开比例降低本轮固定奖励。
- 设计目的：检验骰子利用率和低价值骰的处理能力。

### 7.2 镜面夫人

- 默认结算方向改为从右到左。
- 每轮第一张放入桌间槽的手法牌会在镜像位置生成一个公开的弱化副本。
- 设计目的：检验空间顺序、相邻关系和对称规划。

### 7.3 无面主人

- 三轮分别使用三条预先公开的空间规则。
- 最终轮开始前，玩家从两条公开限制中选择一条生效。
- 设计目的：检验构筑适应性，同时保留玩家主动选择。

## 8. 商店与成长

普通房后进入商店。商店使用情报券，不使用筹码或现金。

每次商店提供：

- 三张可替换的手法牌。
- 一次付费刷新。
- 一项情报服务，可提前查看下一次路线选择中的两组房间规则。

商店不得销售纯粹的永久数值倍率。购买内容应改变目标类型、操作顺序、资源转换或规则处理方式。垂直切片不包含局外永久属性升级；所有基础内容对测试版本开放，便于验证构筑平衡。

## 9. 视觉、界面与交互

### 9.1 美术方向

整体采用“霓虹梦境赌场”：

- 紫色空间作为背景，青色表示规则、合法路径和可交互结构。
- 手法牌使用紫红、象牙白和花色辅助色。
- 骰子具有玻璃或半透明发光材质。
- 庄家使用不断变形的面具和几何轮廓。
- 场景可以扭曲，但规则文字、数值和交互槽位必须保持稳定。

避免老虎机、金币雨、筹码堆、轮盘、赢钱欢呼等现实赌博符号。音效使用玻璃碰撞、合成器脉冲、纸牌摩擦和机械校准声。

### 9.2 三轨规则桌

主界面采用固定的 PC 横屏三轨布局：

- 顶部：区域名称、解析目标、当前轮次和情报券。
- 左侧：庄家形象、本场规则及状态。
- 中央：三张并列规则台、两个桌间槽、骰盘和四张手牌。
- 右侧：逐项结算轨迹、无效原因和本轮总计。

骰子支持拖放，也支持先点击骰子、再点击目标槽。手法牌只高亮合法目标；无效目标显示具体原因。确认结算前，所有分配和出牌均可撤销。

### 9.3 动画与反馈

- 操作后立即刷新预测，不等待动画结束。
- 正式结算按事件列表播放，可加速或跳过。
- 数值变化同时显示来源、旧值和新值。
- 失败界面显示目标差值、失效规则、浪费的骰子和可能改进的决策，不使用笼统的随机失败文案。
- 花色同时通过符号、名称和轮廓区分，不只依赖颜色。
- 设置包含降低闪光、关闭屏幕扭曲、动画速度和界面缩放。

## 10. 叙事

玩家身份是“破局者”，被困在一座把万物变成规则的梦境牌厅。三名庄家分别象征僵硬计算、镜像模仿和无常规则。玩家的目标是理解并破解赌场，而不是赢钱。

叙事通过庄家开场语、区域转换和规则描述传达。垂直切片不制作分支剧情、长篇对话或角色关系系统。

## 11. Godot 工程设计

项目使用 `D:\Godot\Godot_v4.6.1-stable_win64.exe` 对应的 Godot 4.6.1。当前 Mobile 渲染器可继续用于 2D 垂直切片；只有在实际视觉效果需要不受支持的桌面着色器时才切换渲染方式。

### 11.1 建议目录

```text
res://
  scenes/
    run/
    rooms/
    components/
  scripts/
    domain/
    services/
    ui/
  resources/
    cards/
    rule_tables/
    dealers/
    engravings/
  tests/
  docs/
```

稳定的布局和组件层级保存在 `.tscn` 中。脚本负责绑定数据、刷新状态、处理信号和播放事件，不在运行时从脚本拼装整张主界面。

### 11.2 主要组件

- `RunScreen.tscn`：主界面和区域导航。
- `RuleLane.tscn`：单张规则台及骰位。
- `DiceTray.tscn`：骰子显示、选择和拖放。
- `HandPanel.tscn`：四张手牌和目标提示。
- `ResolutionPanel.tscn`：结算轨迹。
- `DealerPanel.tscn`：庄家规则和表现。
- `RunState`：区域、房间、牌组、刻印、情报券和随机种子。
- `RoundState`：骰值、分配、已用手法牌、校准点和操作历史。
- `RuleEvaluator`：验证规则台并生成基础结果。
- `EffectResolver`：执行手法牌、桌间效果、刻印和庄家规则。
- `ContentRegistry`：加载并校验内容资源。
- `RunDirector`：控制区域、房间、商店和失败状态。

内容定义使用自定义 Godot `Resource`。运行时状态使用明确的 GDScript 数据对象，并通过 `to_dict`/`from_dict` 边界序列化，避免把场景节点作为存档数据。

### 11.3 效果模型

四十张手法牌由有限的效果原语组合，不允许每张卡随意执行独立脚本。首批原语包括：

- `adjust_die`
- `reroll_die`
- `swap_dice`
- `copy_die`
- `lock_die`
- `modify_condition`
- `modify_coefficient`
- `repeat_table`
- `reverse_resolution`
- `link_neighbors`
- `grant_intel`
- `refund_calibration`

每个效果资源声明目标类型、参数范围、执行时机和规则文本使用的数值。内容校验器拒绝未知操作、无效目标和越界参数。

### 11.4 数据流

```text
玩家输入
  → ActionValidator 校验
  → 克隆 RoundState
  → EffectResolver 模拟
  → 生成 ResolutionEvent 列表
  → UI 展示预测
  → 玩家确认
  → 原子提交同一结果
  → UI 按事件列表播放动画
```

界面、庄家动画和声音不能自行计算解析值。预览和正式提交共享同一个结算器。

### 11.5 随机与存档

- 所有随机行为使用注入的 `RandomNumberGenerator`。
- 每局保存初始种子；骰子和洗牌不调用全局随机函数。
- 存档只发生在房间边界，不保存半轮状态。
- 存档包含格式版本、完整 `RunState` 和内容版本。
- 写入先生成临时文件，验证成功后再替换正式存档。
- 无法读取的存档显示明确错误并保留原文件，不静默覆盖。

## 12. 错误处理

- 非法拖放返回结构化原因，由界面显示，不静默忽略。
- 内容资源加载失败时列出资源路径、字段和期望值；开发构建阻止进入主局。
- 正式提交前再次校验当前状态，避免动画期间的陈旧操作。
- 结算过程中任何无效引用都终止本轮提交并恢复提交前状态。
- 牌组、骰子和规则台的标识符在存档与运行时保持稳定，不使用节点路径作为内容 ID。

## 13. 测试与验证

垂直切片优先使用无外部依赖的 Godot 无界面自检脚本，并通过以下命令运行：

```powershell
& 'D:\Godot\Godot_v4.6.1-stable_win64.exe' --headless --path . --quit
```

测试分为四层：

1. **规则测试**：枚举最多三颗骰子的全部组合，验证点数、关系和位置条件。
2. **确定性测试**：相同种子与相同操作序列必须生成相同骰值、抽牌顺序和结算事件。
3. **一致性测试**：所有测试局面中，预览总计必须等于正式提交总计。
4. **场景测试**：通过真实按下、移动、释放和点击路径验证拖放、撤销、无效原因和层级遮挡。

内容审计覆盖四十张手法牌、十八张规则台、十二种刻印和三名庄家。每个资源必须具有唯一 ID、可用目标、有效参数、中文规则文本和至少一个正向测试。

可玩性测试记录：

- 每轮合法分配方案数量。
- 校准点、手法牌和撤销的使用情况。
- 未分配骰数量。
- 失败时距离目标的差值。
- 玩家在确认前查看或修改方案的次数。

若固定种子样本中经常只存在唯一解或无解，应修改规则台组合和基础校准能力，而不是通过提高随机收益补偿。

## 14. 垂直切片完成标准

垂直切片完成时必须满足：

- 可从主菜单开始并完成一局包含三地区、九场遭遇的流程。
- 包含四十张手法牌、十八张规则台、十二种刻印和三名庄家。
- 十二张牌组可在商店中进行替换，并保证每场三轮看完全部牌。
- 六颗骰子可分配、收回、校准、受卡牌影响并获得刻印。
- 所有规则、庄家限制和结算变化在确认前可见。
- 所有已支持的操作在确认前可以撤销。
- 自动化样本中预测结果与正式结算完全一致。
- 同一种子和同一操作序列能完整复现。
- 1920×1080 下无规则文本、骰位、手牌或结算轨迹被裁切。
- 花色不依赖颜色识别，并提供减弱闪光和跳过动画选项。
- 游戏中不包含下注、加注、借贷、追损或概率触发的效果。
- 一局由熟悉规则到复合规则形成清晰难度曲线，目标时长处于 30–45 分钟。

## 15. 实施边界

本规格可以作为一个垂直切片实施计划，但实施时应按以下顺序分解：

1. 纯规则模型、固定种子和结算事件。
2. 一张规则台、六颗骰子和完整预览/撤销闭环。
3. 三轨界面与桌间手法牌。
4. 十二张起始牌、牌组循环和商店替换。
5. 三个区域、庄家和骰面刻印。
6. 内容扩展、表现、无障碍与平衡验证。
