# 《六面诡局》梦境玻璃基础 UI 素材设计规格

> 项目：Project Joker
>
> 日期：2026-07-26
>
> 引擎：Godot 4.6.1
>
> 目标分辨率：1920×1080，兼容 1280×720 窗口
>
> 状态：对话设计已确认，等待书面规格复核

## 1. 背景

当前项目使用 `resources/themes/neon_dream_theme.tres` 提供全局
`PanelContainer` 与 `Button` 样式。现有样式已经建立深紫背景、青色交互描边、
紫红按钮和金色区域标识，但除项目图标外尚未形成可复用的基础 UI 图形素材。

首批素材采用已确认的“梦境玻璃牌桌”方向：保留当前色彩语义和布局尺寸，通过
精确的矢量九宫格边框、克制的渐变反光与完整按钮状态，提升界面的材质感和一致性。

基础 UI 框不使用生成式位图。面板圆角、描边、九宫格安全区和按钮状态必须精确对齐，
而生成式位图容易产生不对称边线、不可控细节和拉伸瑕疵。ImageGen 留给后续赌场背景、
区域插画和庄家形象等非结构化素材。

## 2. 目标

1. 建立一套可拉伸、可复用、适合中文规则文本的梦境玻璃基础 UI 素材。
2. 将核心面板和按钮状态接入现有全局 Theme，在真实界面中直接生效。
3. 保持当前布局、内容边距和交互逻辑不变。
4. 让普通、悬停、按下、禁用和键盘焦点状态在深色背景上清楚可辨。
5. 在 1920×1080 与 1280×720 下保持圆角、描边和文字安全区稳定。

## 3. 非目标

- 不重构场景节点、容器结构或业务脚本。
- 不修改卡牌、骰子、刻印、庄家头像或区域背景。
- 不重新设计字体、字号体系和图标系统。
- 不覆盖 `RouteChoicePanel` 等具有金线账簿区域语言的场景专属样式。
- 不在纹理中烘焙文字、数字、图标或语言相关内容。
- 不修改当前工作区中已有改动的 `project.godot`、UI 脚本或测试。

## 4. 视觉语言

### 4.1 共同特征

- 背景以深靛紫为主，中心区域保持高不透明度，保证长文本可读。
- 左上方加入低强度紫红内反光，右下方加入极弱青色冷光。
- 可交互边缘使用青色；普通强调使用紫红；区域专属金色保持独立语义。
- 圆角统一为 12 px 视觉半径。
- 辉光只允许出现在边缘外侧 4 px 范围内，不进入正文文字区域。
- 所有素材保持透明背景，不包含投向场景外部的大面积阴影。

## 6. 九宫格与内容安全区

面板和按钮边框必须完全落在各自的九宫格固定边缘区域内。可拉伸中心不得包含：

- 圆角曲线；
- 独立亮点；
- 单次反射高光；
- 不可重复的噪点；
- 会因双向拉伸而明显变形的图案。

Godot `StyleBoxTexture` 的纹理边距使用素材表中的安全边距。内容边距保持当前 Theme：

- 面板：左 16 px、上 14 px、右 16 px、下 14 px；
- 按钮：左 14 px、上 9 px、右 14 px、下 9 px。

纹理边距负责保护边框，内容边距负责保护文字，两者不得混用。

## 7. Theme 接入

编辑 `resources/themes/neon_dream_theme.tres`：

1. 将面板、按钮四态和焦点框的六个 SVG 声明为外部纹理资源。
2. 为面板、按钮四态和焦点态建立 `StyleBoxTexture`。
3. 将全局映射改为：
   - `PanelContainer/styles/panel` → `panel_glass_9patch.svg`
   - `Button/styles/normal` → `button_glass_normal_9patch.svg`
   - `Button/styles/hover` → `button_glass_hover_9patch.svg`
   - `Button/styles/pressed` → `button_glass_pressed_9patch.svg`
   - `Button/styles/disabled` → `button_glass_disabled_9patch.svg`
   - `Button/styles/focus` → `button_focus_9patch.svg`
4. 保持现有字体颜色和默认字号；只有在实际画面对比度不足时，才允许对同一 Theme 中
   的禁用文字颜色做最小调整。
5. 不修改任何场景尺寸、锚点、容器间距或脚本逻辑。

使用全局 Theme 且没有局部样式覆盖的主遭遇、商店、教学和通用弹窗会自动获得新外观。
场景内显式设置 `theme_override_styles` 的区域专属组件继续使用原样式。
`selection_glow_9patch.svg` 和 `divider_glow_horizontal.svg` 保持为独立配套素材，
本批次不在 Theme 中创建未使用的映射。

## 8. 交互状态

### 8.1 普通

紫色主体配紫红描边。边缘清晰，但不产生明显外发光，避免大量按钮同时出现时画面过亮。

### 8.2 悬停

主体亮度小幅提高，描边切换为青色。状态差异不能只依赖辉光，描边颜色必须发生变化。

### 8.3 按下

主体切换为深青色，描边提高亮度。不得通过缩小纹理或改变按钮内容边距模拟按压，
避免文字和相邻控件跳动。

### 8.4 禁用

降低主体和描边的对比度，继续保留可识别轮廓。禁用态不能只依赖降低文字透明度。

### 8.5 键盘焦点

使用透明中心和粉白色外框。焦点框位于按钮主体外缘，不遮盖按钮本身的状态描边，
并在普通、悬停和按下状态下都保持可见。

## 9. 工作区边界

- 新增 `resources/ui/dream_glass/` 下的素材；
- 修改 `resources/themes/neon_dream_theme.tres`；
- 使用 `tmp/` 保存临时导入或视觉验证文件；
- 更新本设计规格的状态。

不得编辑、暂存或提交现有未提交的 `project.godot`、UI 脚本、测试和其他设计文档。
本设计文档按项目约定只暂存，不提交。

### 10.1 静态检查

- 每个 SVG 具有正确的 `viewBox` 和透明背景。
- 文件不含文字、外部字体、位图嵌入或外部链接。
- 九宫格安全区内不存在会被拉伸破坏的边角细节。
- Theme 中所有纹理路径均可由 Godot 成功加载。

### 10.2 引擎导入

使用 Godot 4.6.1 执行一次无头编辑器导入并退出，确认：

- 无 SVG 解析错误；
- 无丢失纹理或 Theme 子资源错误；
- 项目启动时无新增错误。

### 10.3 自动验证

运行现有全量测试入口 `res://tests/run_all.gd`，并重点关注：

- `ui_component_contract_test.gd`
- `single_encounter_layout_self_check.gd`
- `single_encounter_input_self_check.gd`

### 10.4 视觉验证

在真实运行画面中检查：

1. 1920×1080 视口下的主遭遇界面；
2. 1280×720 窗口下的主遭遇界面；
3. 至少一个带长中文规则文本的面板；
4. 普通、悬停、按下、禁用和键盘焦点五种按钮状态；
5. 极窄按钮与宽按钮上的九宫格边缘；
6. 面板相邻排列时是否出现重复辉光或过亮接缝。

验收要求为：无圆角变形、无边线拉粗、无文字对比度下降、无控件尺寸变化、
无输入路径回归。

## 11. 风险与处理

### SVG 导入产生边缘模糊

优先将描边放在整数像素坐标并使用偶数描边宽度；仅在实际导入后仍模糊时调整
SVG 导入缩放，不通过修改控件尺寸掩盖问题。

### 九宫格纹理出现接缝

检查边距是否切到渐变或描边中间。修正素材与 `StyleBoxTexture` 边距，使固定边缘完整，
不在 Theme 中增加补偿性扩展边距。

### 全局 Theme 改动影响区域专属界面

以场景中的显式 `theme_override_styles` 为边界。金线账簿等专属样式保持覆盖；
只有继承全局 Theme 的通用表面发生变化。

### 辉光降低长文本可读性

降低内反光和边缘辉光透明度，保持中心背景不透明度；不通过加粗全部字体解决。
