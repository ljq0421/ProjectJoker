# 《六面诡局》十八项基础规则台目录设计规格

> 文档日期：2026-07-29
> 上位规格：`2026-07-24-six-sided-rulebreakers-design.md`
> 适用引擎：Godot 4.6.1
> 状态：设计已确认
> 文档边界：只暂存，不提交

## 1. 目标

本阶段建立十八项可审计、可复用、可参数化的基础规则台目录，并让玩家可在
独立的“规则档案室”中实际体验全部规则。

本阶段解决以下问题：

1. 现有 `RuleDefinition` 只支持精确总和、全偶和连续数列三类条件。
2. 规则台目前嵌入房间与庄家资源，没有独立、稳定的模板目录。
3. 当前骰子分配只记录放入顺序，不能表达明确空槽与指定槽位。
4. 点数、关系、位置和扭曲四类规则尚未形成统一的评估与事件模型。
5. 新规则若只存在于测试中，玩家无法验证其可读性与策略价值。

完成本阶段后：

- 目录中恰好存在十八个全局规则模板。
- 房间中的规则台作为参数化实例引用目录模板。
- 十二个普通房、三名庄家及无面主人三轮日程完成无行为回归迁移。
- 玩家可从主菜单进入六组固定的规则档案室练习。
- 预演与正式提交继续共享同一解析路径。

## 2. 范围与非目标

### 2.1 包含

- 十八个 `RuleTableTemplate` 资源。
- 显式路径驱动的 `RuleTableCatalog`。
- 模板驱动的参数化 `RuleDefinition`。
- 十八种规则所需的条件评估。
- 显式骰位、精确槽位放置和原子交换。
- 回声、反向和桥接三种规则台扭曲效果。
- 六组规则档案室练习及主菜单入口。
- 内容审计、穷举规则测试、可玩性检查、布局和真实输入验收。
- 现有三个地区、教程、设置、音效和导航回归。

### 2.2 不包含

- 重新平衡现有三个地区。
- 把新增规则重新编排进现有地区房间。
- 连续三区域远征或跨区域状态继承。
- 商店付费刷新与路线情报服务。
- 房间边界存档。
- 新手法牌、新刻印、新庄家或第三刻印槽。
- 局外永久成长、随机隐藏规则或概率触发奖励。
- 结算动画、无障碍设置或叙事扩展。

新增规则在本阶段只进入规则档案室。后续连续远征阶段再从目录中编排正式
房间，避免目录建设与既有地区平衡重做同时发生。

## 3. 已确认的产品决策

- 实现四大类别下十八种真正不同的规则语义，不以目标数值变体凑数量。
- 使用“全局模板 + 房间参数化实例”两层模型。
- 现有地区的数值、目标、通关难度和固定种子结果保持不变。
- 位置规则使用真实、可交互的槽位顺序。
- 扭曲效果进入领域层统一预演和正式结算，不由 UI 推断。
- 新增规则通过六组独立练习对玩家开放。
- 档案室不产生情报券、刻印、地区进度或持久化解锁。
- 所有规则、方向、代价和非法原因在提交前公开。
- 不新增重投、下注、加注、追损、借贷或概率触发奖励。

## 4. 两层规则资源模型

### 4.1 `RuleTableTemplate`

`RuleTableTemplate` 是全局、不可在房间内改写的规则语义模板，至少包含：

- `id: StringName`
- `display_name: String`
- `description: String`
- `category: Category`
- `condition_kind: ConditionKind`
- `post_pass_effect: PostPassEffect`
- `minimum_slot_count: int`
- `maximum_slot_count: int`
- `compatible_condition_modifiers: Array`

类别枚举：

- `POINT`
- `RELATION`
- `POSITION`
- `DISTORTION`

条件类型至少覆盖：

- `ANY_FILLED`
- `EXACT_SUM`
- `MINIMUM_SUM`
- `MAXIMUM_SUM`
- `SUM_RANGE`
- `ALL_EQUAL`
- `ALL_DISTINCT`
- `ALL_EVEN`
- `ALL_ODD`
- `SAME_PARITY`
- `CONSECUTIVE`
- `FIXED_DIFFERENCE`
- `STRICT_ASCENDING`
- `STRICT_DESCENDING`
- `MIRRORED`
- `SLOT_TARGETS`

通过后效果：

- `NONE`
- `ECHO_SELF`
- `REVERSE_DIRECTION`
- `BRIDGE_FORWARD`

### 4.2 `RuleDefinition`

`RuleDefinition` 表示某场遭遇中的规则台实例，至少包含：

- `id: StringName`
- `display_name: String`
- `template: RuleTableTemplate`
- `slot_count: int`
- `target_value: int`
- `minimum_value: int`
- `maximum_value: int`
- `difference: int`
- `slot_targets: PackedInt32Array`
- `coefficient: int`
- `flat_bonus: int`

实例只填写当前房间的数值参数，不复制模板的条件语义或扭曲效果。最终代码
不长期保留旧 `ConditionType` 与模板条件并行的双轨路径。

### 4.3 `RuleTableCatalog`

`RuleTableCatalog` 使用十八条显式资源路径加载模板，不依赖目录遍历顺序。
目录提供：

- `all_templates()`
- `all_ids()`
- `find_template(template_id)`
- `templates_for_category(category)`
- `validate()`

目录必须验证：

- 模板数量恰好为十八。
- ID 唯一且稳定。
- 点数、关系、位置、扭曲数量分别为 `4 / 7 / 4 / 3`。
- 名称、说明、骰位范围和条件类型有效。
- 条件修饰白名单只包含已支持组合。

## 5. 十八项基础规则台

### 5.1 点数台

1. **精确总和**：总和等于公开目标。
2. **最低总和**：总和不低于公开目标。
3. **最高总和**：总和不高于公开目标。
4. **区间总和**：总和处于公开闭区间。

### 5.2 关系台

5. **全部同点**：所有骰子点数相同。
6. **全部不同**：所有骰子点数互不相同。
7. **全偶**：所有骰子均为偶数。
8. **全奇**：所有骰子均为奇数。
9. **同奇偶**：所有骰子奇偶一致，可全奇或全偶。
10. **连续数列**：排序后逐项相差一。
11. **固定差值**：排序后相邻差值均等于公开参数；参数至少为二。

### 5.3 位置台

12. **严格升序**：按槽位从左到右严格递增。
13. **严格降序**：按槽位从左到右严格递减。
14. **镜像排列**：首尾、次首尾等对应槽位点数相同。
15. **指定槽位**：每个槽位分别等于公开目标值。

### 5.4 扭曲台

16. **回声台**：填满即通过；结算自身基础得分后再公开重复一次。
17. **反向台**：填满即通过；在事件结算前翻转本轮处理方向。
18. **桥接台**：填满即通过；若最终方向上的下一张相邻台也通过，额外传递
    一次本台基础得分。

三个扭曲模板使用低于条件台的系数。回声和桥接只复制规则台的基础得分，
不复制卡牌重复、刻印、庄家奖励或其他扭曲效果。

## 6. 显式骰位与交互

### 6.1 状态

每条规则轨的分配使用固定槽位数组。空槽使用明确空标记，不能通过压缩数组
掩盖中间空位。克隆、撤销、预演和提交必须保留完整槽位位置。

所有遍历已分配骰子的逻辑必须跳过空标记。骰子仍然只能占用一个槽位。

### 6.2 操作

- 每个骰位是独立点击和拖放目标，并显示稳定位置编号。
- 选中骰子后点击空槽，将骰子放入该槽。
- 拖放到具体空槽，执行相同操作。
- 点击整条规则轨或拖到轨道空白处，使用第一个空槽。
- 两颗已分配骰子之间可以原子交换，包括跨规则轨交换。
- 未分配骰子不能挤走已占用槽位中的骰子。
- 一次移动或交换只生成一个撤销快照。
- `Esc` 取消当前选择，不改变业务状态。

任何操作完成后立即刷新条件结果、方向和结算预演。

### 6.3 非法原因

至少提供以下具体原因：

- `目标骰位已占用`
- `规则轨已经放满`
- `骰子不存在`
- `规则台模板不存在`
- `该手法牌不能修改当前规则条件`
- `指定槽位目标与骰位数量不一致`

非法操作必须保持骰子位置、手牌、校准点和撤销历史不变。

## 7. 条件评估

`RuleEvaluator` 使用实例引用的模板决定判定分支，并使用实例参数计算结果。

评估输入中的骰子顺序等于真实槽位顺序：

- 点数与无序关系条件可以忽略顺序。
- 升序、降序、镜像和指定槽位必须保留顺序。
- 固定差值先排序，再检查所有相邻差值。
- 空槽导致规则台未满足，并显示所需骰位数。

基础公式保持：

`规则台结果 = 已分配骰子的点数总和 × 收益系数 + 固定奖励`

现有条件宽容只兼容以下模板：

- `EXACT_TOLERANCE` → 精确总和。
- `ALLOW_ONE_ODD` → 全偶。
- `ALLOW_ONE_GAP` → 连续数列。
- `INCREASE_SLOT_COUNT` → 模板明确允许扩充骰位时生效。

指定槽位不兼容扩充骰位。对不兼容模板出牌时必须在出牌阶段拒绝，不能等到
提交时静默忽略。

## 8. 统一结算数据流

结算器按以下阶段运行：

1. 应用手法牌产生的有效骰值、系数、条件修饰和卡牌方向反转。
2. 按真实槽位顺序预判全部规则台是否通过，暂不累计分数。
3. 依次组合地区基础方向、卡牌反转和已通过反向台，计算唯一最终方向。
4. 按最终方向生成规则台基础事件，并保持现有卡牌重复、刻印和失败事件顺序。
5. 在回声台基础事件后生成一次独立回声事件。
6. 所有基础规则台处理完成后生成桥接事件。
7. 处理庄家奖励和整轮汇总。

多个反转按次数奇偶叠加。方向必须在任何得分事件播放前确定，并写入
`ResolutionReport`。

桥接台只能配置在中间轨，确保两个可能方向下均存在相邻台。目标台未通过时
仍生成零增量事件并说明原因。桥接使用本台单次基础得分，不形成递归或循环。

预演和正式提交调用同一解析器。UI 只渲染 `ResolutionReport`，不自行判断
模板条件、最终方向、回声次数或桥接目标。

## 9. 现有内容迁移

现有精确总和、全偶和连续数列分别迁移到模板：

- `rule_exact_sum`
- `rule_all_even`
- `rule_consecutive`

迁移覆盖：

- 金线回廊四个普通房与铁算盘。
- 反照牌厅四个普通房与镜面夫人。
- 无面中枢四个普通房。
- 无面主人三轮日程中的三组遭遇。
- 基础教学、单场练习和所有测试夹具。

迁移不改变：

- 轨道 ID。
- 中文显示名。
- 骰位数量。
- 目标值、系数和固定奖励。
- 房间累计目标与情报奖励。
- 地区种子、牌组、商店候选或刻印。
- 现有预演与提交事件总分。

最终内容审计拒绝任何正式房间或庄家继续使用空模板或目录外模板。

## 10. 规则档案室

### 10.1 入口与页面

主菜单新增“规则档案室”入口。档案室页面列出六个始终开放的档案，不设解锁
顺序或持久化进度。

选择档案后复用现有单场遭遇界面和统一结算器。完成页提供：

- `再次练习`
- `返回档案室`
- `返回主菜单`

所有返回路径必须通过真实鼠标点击验证。

### 10.2 六组练习

| 档案 | 三张规则台 |
|---|---|
| 01 点数边界 | 精确总和、最低总和、最高总和 |
| 02 集合判断 | 区间总和、全部同点、全部不同 |
| 03 奇偶协议 | 全偶、全奇、同奇偶 |
| 04 序列关系 | 连续数列、固定差值、严格升序 |
| 05 槽位秩序 | 严格降序、镜像排列、指定槽位 |
| 06 空间扭曲 | 回声台、桥接台、反向台 |

每个档案：

- 三张规则台的总骰位恰好为六。
- 使用固定骰面、固定基础手牌和两点校准。
- 只进行一轮。
- 允许撤销和无限重试。
- 不发放情报券、刻印、地区奖励或持久化进度。
- 不强制指定解法或要求使用某张手牌。
- 至少存在两种能让多张规则台得分的有效方案。

位置档案在每个槽位显示位置编号和目标提示。扭曲档案明确显示最终方向、
回声来源和桥接目标；桥接台固定在中间轨。

## 11. 内容校验与错误处理

### 11.1 模板参数

- 区间下限不得高于上限。
- 点数目标必须处于当前骰位可达范围。
- 固定差值至少为二，且存在合法骰面组合。
- 指定槽位目标数量必须等于骰位数。
- 每个指定目标必须处于一至六。
- 模板骰位数必须处于模板允许范围。
- 系数必须为正。
- 桥接模板实例只能位于中间轨。

### 11.2 加载失败

目录资源缺失、类型错误、模板重复或实例参数错误时，错误信息列出资源路径、
模板 ID、实例 ID、字段与期望范围。开发构建阻止进入对应玩法，不用默认模板
静默替代。

### 11.3 结算失败

结算中发现未知骰子、重复占位、目录外模板或无效参数时，本轮报告标记为
无效，不修改正式状态，也不产生部分奖励。

## 12. 测试与验收

### 12.1 模板与目录

- 精确验证十八个模板 ID。
- 验证四类数量为 `4 / 7 / 4 / 3`。
- 验证资源路径、名称、说明和参数约束。
- 验证重复 ID、目录外引用和无效参数被拒绝。

### 12.2 条件与可达性

- 对各模板枚举合法与非法骰面组合。
- 验证边界包含关系、排序语义和位置顺序。
- 验证每个档案至少有两种多台得分方案。
- 固定差值、区间和指定槽位必须有可达性检查。

### 12.3 槽位与撤销

- 点击具体槽位和拖放到具体槽位。
- 点击轨道自动使用第一个空槽。
- 同轨与跨轨原子交换。
- 已占用槽位非法原因。
- 一次交换一次撤销。
- `Esc` 只取消选择。

### 12.4 扭曲与事件

- 单次与多次方向反转。
- 卡牌反转与反向台叠加。
- 卡牌重复与回声分别记录，互不递归。
- 桥接目标通过、失败及两个最终方向。
- 预演与正式提交的方向、事件、增量和总分完全一致。

### 12.5 回归

- 三个旧地区的固定种子、目标、总分和事件保持一致。
- 金线回廊、反照牌厅、无面中枢端到端通过。
- 基础教程、三个地区引导、设置和音效通过。
- 主菜单、档案室、练习完成页和返回路径通过真实鼠标点击。
- `1280×720` 与 `1920×1080` 下无裁切或重叠。
- 主场景 headless 启动无脚本加载或编译错误。

所有 Godot headless 命令必须提供写入 `$env:TEMP` 的显式 `--log-file`。
失败条件为退出码非零，或者日志包含 `SCRIPT ERROR|Failed to load script`。
已知证书、故意损坏配置、未知 SFX 与退出资源泄漏噪声不单独视为脚本失败。

## 13. 实施边界

实施按以下顺序拆分：

1. 模板资源、目录与目录审计。
2. 参数化实例与新条件评估。
3. 显式槽位、交换、撤销和 UI。
4. 现有全部内容与测试夹具迁移。
5. 扭曲效果与统一事件流。
6. 六个档案资源、档案室页面和主菜单入口。
7. 全量回归、双分辨率、真实输入和可玩性验收。

每项代码提交使用显式路径或 `git commit --only`。本规格及后续实施计划只
暂存，不进入代码提交。

## 14. 完成标准

- 十八个模板均为独立规则语义。
- 四大类别数量准确，目录可按 ID 和类别查询。
- 正式内容全部引用目录模板。
- 现有三个地区的玩法和平衡无回退。
- 玩家可完整进入并完成六个规则档案。
- 位置台基于真实槽位顺序工作。
- 三种扭曲效果公开、确定、可预演且不可递归。
- 所有非法操作保持状态原子性并显示具体原因。
- 预演与正式提交完全一致。
- 全量自动测试、真实输入、布局和主场景启动验收通过。
- 设计文档和实施计划保持只暂存、未提交。
